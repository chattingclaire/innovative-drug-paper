# 恢复完整资料

常用论文、数据、图表和代码可直接在仓库中浏览；完整过程资料存放在私有仓库 `chattingclaire/innovative-drug-paper` 的 `archive-20261016` Release，文件名为 `archive-001.tar.gz` 等。

恢复工具只使用 Python 3 标准库。自动下载另外需要已经登录且有本仓库访问权限的 GitHub CLI（`gh`）。工具不读取、打印或保存登录令牌。

请先取得完整仓库，保留 `90-完整归档/归档总览.json`、`全部文件清单.jsonl.gz` 及 `内部研究链接映射.json`。也支持未压缩的 `全部文件清单.jsonl`，两者同时存在时优先读取压缩版。在仓库根目录运行下列命令；路径可改成自己的位置。

## 自动下载并核验

```bash
python3 99-整理与恢复工具/restore_archive.py \
  --archives "$HOME/Downloads/创新药论文归档包" \
  --download \
  --verify-only
```

这会下载本地尚不存在的包，按归档总览核对每包 SHA-256，检查所有成员的路径、类型、数量和大小，再核对选定包内每个文件的 SHA-256。同时检查内部研究链接映射的安全路径、普通文件目标或目录下全部目标文件、来源锚点及其包归属。`--verify-only` 不解压、不创建链接，也不核验其他位置曾经解压的副本。已有包不会被下载覆盖；已有包损坏时会报错，需自行移走损坏包后重试。

## 恢复全部资料

```bash
python3 99-整理与恢复工具/restore_archive.py \
  --archives "$HOME/Downloads/创新药论文归档包" \
  --destination "$HOME/Desktop/创新药论文-完整恢复" \
  --download
```

已手动下载全部包时，省略 `--download`。恢复目录必须不存在或完全为空，且不能位于归档记录的任何原始来源目录内。工具先完成全部选定包的 SHA-256 和成员预检，随后才写入文件；逐文件写入后再核对其 SHA-256。任何已有文件均不会被覆盖。tar 包内的符号链接、硬链接、设备等特殊成员以及绝对路径、`..` 越界路径始终拒绝解压。

普通文件全部恢复和校验后，工具按独立映射安全重建17个内部研究引用：9个元数据文件链接、8个材料目录链接。实际创建的是指向恢复树内部的相对链接，并逐条核验解析位置与目标类型；映射中保留的原始绝对 `target` 文字只作历史记录，绝不会用于连接本机旧来源目录。目录目标必须对应文件清单中一个完整的普通文件子树，不能指向自身、祖先、后代或包含另一映射链接，避免循环。不在此映射中的外部 `node_modules` 等依赖链接不会重建。若缺失映射文件，工具会明确提示仅处理普通归档文件，不能视作内部引用已经恢复。

包内保持以下六个原始来源根目录名称和相对路径。分包只为便于存储和下载，不改变恢复后的原始层级；某个根目录可能分布在多个包中。

- `药企项目-创新药`
- `创新药论文-完整归档-20260914`
- `创新药论文.md`（这是原始目录名称）
- `创新药动态简报`
- `美国生物医药产业研究`
- `创新发展政策导论`

恢复时保留普通文件的权限位和修改时间，不恢复原机器的所有者身份。归档中已脱敏文件按清单的 `archived_sha256` 校验；`source_sha256` 仅供追溯原始版本，不能用于核验脱敏后的归档副本。可重装依赖、缓存、系统元数据及未收录链接详见 `90-完整归档/未上传的依赖缓存与系统文件.csv`；其中17个内部研究链接由补充映射恢复，其目标普通文件已在归档内。

## 仅核验或恢复部分包

```bash
python3 99-整理与恢复工具/restore_archive.py \
  --archives "$HOME/Downloads/创新药论文归档包" \
  --bundle archive-001.tar.gz \
  --bundle archive-002.tar.gz \
  --verify-only
```

`--bundle` 可重复指定，名称须与归档总览一致。只核验所选包内的文件内容，不要求其余包已经下载；为核对内部链接归属，会读取完整文件清单。配合 `--download` 时只下载所选包。部分恢复只重建来源父目录确实随所选包恢复、且目标已完整恢复的内部链接；目录链接要求其前缀下全部目标文件均在所选包内。缺少完整目标或来源目录的链接会跳过并单列数量。要解压这些包，将 `--verify-only` 换成 `--destination "一个新的空目录"`。部分恢复不代表完整归档已经恢复；需要多个包时请一次选齐，工具不会向已有内容的目录追加恢复。

工具默认从脚本上级仓库目录的 `90-完整归档` 读取元数据。单独复制脚本使用时，可额外指定 `--metadata "元数据所在目录"`。全部参数可通过 `python3 99-整理与恢复工具/restore_archive.py --help` 查看。

## 中断或校验失败

包 SHA-256 或成员预检失败时不会开始解压。文件内容校验失败、磁盘写入失败或人为中断可能留下部分恢复文件；工具保留这些文件供排查，不自动清理，也不会继续覆盖。确认原因后，请使用另一个新空目录重新恢复。

恢复工具已经使用微型临时归档验证正常恢复、权限和时间保留、压缩清单、错误包与文件哈希、路径越界、tar链接拒绝、重复成员、覆盖保护、原始来源保护、单包选择及模拟 `gh` 下载；另验证内部文件和目录链接的相对重建、跨根目录目标、目录目标跨包未齐时跳过、映射越界/清单外目标/错误包/循环拒绝及链接位置覆盖保护。未在此过程中运行论文研究脚本。原研究代码中的绝对路径和运行依赖仍须按实际环境调整，资料恢复本身不等于研究结果已重新计算。

## 单独从Release下载恢复工具

Release为避免中文附件名被自动改写，元数据分别命名为 `archive-summary.json`、`manifest.jsonl.gz`、`manifest.csv.gz`、`internal-links.json`、`integrity-report.json` 和本说明 `RESTORE.md`。内容与仓库中的中文文件相同。将 `restore_archive.py`、三份必需元数据（archive-summary、manifest.jsonl、internal-links）及归档包放在同一新目录，使用 `--metadata "该目录" --archives "该目录"` 即可；工具同时支持仓库中的中文名称与这些英文别名。
