本提示只细化执行顺序，不改变 `CAL-5D-20260926-v1.3` 的五维定义、纳入边界或子类型。运行时必须在本提示后原样附上冻结的 `protocol-v1.3.md` 及适用的共同澄清；若本提示与冻结协议冲突，以冻结协议为准。

## 一、两阶段门禁

### 阶段 A：材料完整性校验与补料闭环

先逐条检查 `text` 和 `contexts` 是否足以确定当前单元的对象、命题、适用条件、指代和表格列关系。

- 若源文缺字、截断、错列，或缺失的上位条件会改变整个单元的含义，不得猜测，不得用0代替缺料，也不得产生该条最终标签。进入补料队列，逐条保存ID、缺失内容、所需材料、回源状态和补料后的文本版本。
- 补料队列必须覆盖所有未通过门禁的ID。不得删除困难条目、改ID或只保留容易判定的条目。
- 完整自足的句子不因没有更多父段而进入补料队列。只有能够具体说明缺失了什么，且该缺失会影响理解时，才补料。
- 补料完成后必须从同版完整原文和上下文重新阅读。旧待定、临时判断或旧标签不能直接转成最终标签。
- 阶段A的补料队列不是最终编码文件，不使用二元输出Schema，但必须留存并可与冻结输入ID逐一核对。

### 阶段 B：完整ID集的最终二元编码

只有全部冻结ID都通过材料门禁后，才按既有 `output_schema_binary.json` 发布结果。最终 `labels` 中S、E、Ec、I、F只能为整数0或1；文本问题、语境问题或边界备注另记在顶层 `issue_records`。

发布前必须校验最终结果的ID集合、条数和顺序与冻结完整输入完全一致。只要仍有一个ID缺料，整批状态就是“未完成”，不得声明已完成全量编码，不得以0填补，不得排除这些条目后报告全量结果、准确性、一致性或其他指标。

这里的二元发布是用户授权的最终输出约定，不改变冻结手册的语义定义，也不表示冻结手册原始三态记录规范不存在。

## 二、每条必须执行的语义顺序

对每一条记录独立完成以下步骤，不得批量套用模板，不得先找词再决定标签。

1. **读完整单元。** 完整阅读 `text`；再阅读全部所附 `contexts`。不得只读预览、前若干字或搜索命中片段。
2. **确定对象。** 用一句内部判断明确当前句究竟在说什么对象，例如药物疗效、用药风险、申报文件格式、专家经历、药品供应状态、医保支付标准或一般机构管理。
3. **提取命题。** 明确当前单元对该对象实际作出的要求、判断、比较、信息收集或制度安排。名称、背景、栏目名和程序身份不等于实质命题。
4. **逐维寻找证据。** 分别判断 S、E、Ec、I、F。每个 1 必须能回答：“当前单元中的哪段连续原文，直接支持哪个维度命题？”
5. **做排除核对。** 每个 0 都是已读后的实质判断。若当前句出现接近 I 或 F 的概念，I=0 或 F=0 的理由必须指出该表述及其仍不满足的排除边界；若当前句完全没有相近概念，应具体说明当前命题实际只涉及什么以及没有形成 I/F 命题，不得虚构一个“最近边界”。
6. **限制上下文用途。** 上下文可用于消解对象、明确指代、比较基准、适用条件、缩写、列含义和当前句已经指向的保障关系。不得把父段、标题或适用范围中的 S/E/Ec/I/F 自动复制到当前单元。禁止背景传播不等于忽视有明确语法或语义指向的上文；判断关键是当前命题是否通过指代、比较或条件关系实际承接该上文。若 1 依赖上下文，除当前单元引文外，再给出所依赖的连续上下文引文。
7. **最后才写 JSON。** 标签、理由、证据和子类型必须来自本条已经完成的语义判断。脚本只可组装和校验这些逐条判断，不得读取文本后按关键词、正则、词表、字符串匹配或启发式规则生成标签、理由、证据或子类型。

## 三、五维执行边界

五维定义完全沿用 CAL-5D v1.3。以下只强调容易误判的执行边界。

“实质讨论”不要求已经得出肯定结论。明确要求评价、比较、收集、提交或补充某维度的内容或证据，按该维度处理，即使尚未给出结果。条件、否定、不确定性、效果不足或证据不足的陈述，仍可能是在讨论相应维度；不得因语气为否定、未确定或待补证据而自动判0。事务性的文件名、上传格式、保密、公开、时间和流程要求，只有在同时新增相应评价内容要求时才按实际内容命中。

### S 安全性

当前命题必须实质涉及药物或用药损害及其识别、评价、预防或控制。数据安全、基金安全、一般生产安全、一般质量管理、人员经历和程序时限不自动属于 S。缩写只有在当前材料中已被可靠释义并用于当前命题时才可据此判断。

明确“药品质量安全”或“质量风险”可按冻结手册判断S；仅有一般质量、工艺、稳定性或生产规范不自动赋S。最终输出保留 `safety_quality_basis`：S=1且仅依据明确药品质量安全/质量风险时为 `quality_only`；同时有其他药物损害依据时为 `quality_and_other`；没有质量安全依据时为 `no_quality_basis`，包括S=0，以及S=1但仅依据不良反应等其他药物损害的情形。最终二元发布不使用 `undetermined`。

### E 有效性

当前命题必须实质涉及药物防治效果、临床获益、治疗优势、疗效终点、相关生活质量、指南药物治疗推荐，或明确为这些判断收集、比较、提交证据。试验设计、证据质量、代表性或药代动力学本身不自动属于 E。

E 与 I 相互独立。有效性从来不要求同时出现创新、新颖、注册分类或创新资格。只要当前单元直接讨论药物效果或临床获益，即可独立判断 E；不得因 I=0 而把 E 改为 0，也不得因 E=1 而推定 I=1。

### Ec 经济性

当前命题必须实质涉及药品价格、药费、治疗成本、支付标准、报销和费用责任、相关销量或金额、成本效果、预算影响或药品支付对基金的影响。仅有谈判流程、支付范围名称、文件名、行政收费或一般基金安全不自动属于 Ec。

### I 创新性

I=1 必须有当前单元中的具体创新命题，并对应至少一个有独立证据的子类型：

- `attribute`：明确讨论或要求评价药物创新属性、原创/改良、新颖机制或靶点、相关知识产权、注册创新分类，或创新属性信息；
- `research_support`：明确规定、提供、扩大或讨论针对药物研发创新的支持措施；
- `qualification_advantage`：当前条款明确识别创新/改良资格，并实质陈述该资格所要求的临床比较优势或治疗突破。

以下内容单独出现时 I=0：把“创新药”当作药品类别或支付对象；“罕见病药品”“新药”“新品种”“新剂型”“新规格”等名称；普通作用机制；一般临床价值；突破性治疗、优先审评、附条件批准等程序名称；新的管理流程、数字系统或工作方式；一般产业发展或研发效率背景。

I=0 的理由不能只写“未涉及创新性”。若本条存在接近创新性的表述，必须指出该表述，并说明它为何只是类别名称、程序身份、一般研发背景、普通机制、事务性知识产权事项或其他明确排除项。若本条完全没有相近概念，应说明当前命题实际只涉及何事，并明确其没有形成药物创新属性、创新资格或研发创新支持命题。

### F 公平性

F=1 必须有当前单元中的具体保障获取、患者可负担、药品临床管理难度，或明确但未细分的公平性资料要求，并对应至少一个有独立证据的子类型：

- `access`：弥补用药保障空白、改善药品可及、具体药品配备或持续供应、短缺、常规治疗获取渠道，或防止不合理的用药获取限制；
- `affordability`：患者支付能力或药费负担；
- `clinical_management`：针对该药使用的具体管理障碍、复杂性或监测负担，或明确评价这类难度；
- `dimension_information`：只明确要求公平性信息，未给出可细分内容。

以下内容单独出现时 F=0：儿童、老年、罕见病或其他重点人群名称；创新药、基本目录、商保目录或申报资格；试验代表性、一般受试者参与便利；适老化包装、吞咽或给药便利；医院一般管理、处方规范或公平竞争；宏观医保筹资、机构建设或医疗服务均等化而没有明确药品使用/保障联系；一般配送、签收或文件报送事务。

F=0 的理由不能只写“未涉及公平性”。若本条存在接近公平性的表述，必须指出该表述，并说明它为何只是人群/目录/资格名称、研究参与问题、一般便利性、行政管理、宏观制度背景或配送事务，而没有形成保障获取、可负担或临床管理难度命题。若本条完全没有相近概念，应说明当前命题实际只涉及何事，并明确其没有形成上述保障命题。

供应内容按冻结手册判断当前命题是否已经形成明确的药品保障获取含义。具体药品配备、持续供应、短缺或要求报告这些状态可构成 `access`；目的性或较抽象的供应条款须结合其对象、谓词以及与基本用药保障的关系独立判断，并在边界事项中留下具体理由。不得仅因没有量化指标、具体药品名称或逐项配备状态就自动排除 F，也不得只因出现“供应”二字就自动赋 F。

## 四、理由与逐字证据

- 五个维度都必须有针对当前条目的简短理由。禁止使用“原文实质涉及本维度”“未实质讨论本维度”等可跨条目复制的固定理由。
- I、F 的理由必须具体写出对象和命题。存在相近概念而判 0 时必须写明排除边界；完全没有相近概念时，写明当前实际命题及不存在 I/F 命题即可，不得编造边界。
- 每个 1 至少有一条 `source="unit"` 的证据。`quote` 必须逐字复制 `text` 中的一段连续原文，不得改标点、拼接、插入省略号或用解释替代引文。
- 若标签依赖上下文消解，再增加 `source="context"` 的连续逐字引文。上下文引文只支持被消解的对象、条件、指代、缩写或列关系。
- 证据应尽量截取能独立支持判断的最短完整片段。短句本身不可再缩时可引用整句；长段不得为省事全部复制。
- 0 通常不要求证据，但理由必须说明当前命题为何落在定义之外。
- I、F 子类型只能在相应标签为 1 时填写；每个子类型必须由该条理由和证据直接支持。不得为了字段完整而猜测。

## 五、独立性与发布纪律

- 不读取参考标签、其他方法结果、另一评审答案、正类比例、评价指标或论文预期结论。
- 不因希望提高一致率、κ、准确率或某维度正类数而调整标签。
- 不重跑全部材料来挑选更有利结果；格式或引文录入更正必须保留首次输出并另存更正记录。
- 最终结果是 LLM 方法的独立预测，不声称人工金标准。

## 六、输出前逐条自检

对每条依次确认：

1. 我已经读完 `text` 和所有给定 `contexts`。
2. 每个标签都来自当前单元的对象与命题，而非关键词出现。
3. 父段和标题只用于消解，没有传播无关维度。
4. E 没有被错误要求必须同时满足创新性。
5. “创新药/新药/罕见病/重点人群/目录资格”没有被直接转成 I 或 F。
6. I、F 的理由是本条专属理由；为 0 且存在相近概念时写明排除边界，完全无相近概念时准确说明当前命题即可。
7. 每个 1 都有当前单元的连续逐字引文；依赖上下文时另有上下文引文。
8. 标签只有整数 0 或 1；问题状态只在 `issue_records` 中记录。

## 七、执行调整与旧机制问题对应

本节说明为何增加上述执行约束，不改变任何维度定义。

| 执行调整 | 对应的旧机制问题 | 本版控制方式 |
|---|---|---|
| 强制先识别对象与命题，再逐维找证据 | 关键词出现可能被误当作评价内容，例如把人员经历中的领域词当成药物风险评价 | 先写清句子在谈药物价值、人员经历、文件格式还是程序安排；只有当前命题落入维度定义才可赋 1 |
| 上下文限于指代、比较、条件、缩写、列义和已承接的保障关系 | 旧 LLM 容易把父段中的“创新药”“安全、有效”或研发背景传播到后续技术定义 | 当前单元必须有承接锚点；有明确指代时读取并使用上文，无承接锚点时不得复制背景维度 |
| I 必须给出具体创新命题及子类型证据 | “创新药”、程序身份、普通机制、一般研发效率容易触发过宽的 I | 要求区分药品类别名称、创新属性、创新资格与研发创新支持；名称本身不构成 I |
| F 必须给出保障关系及子类型证据 | 罕见病、儿童/老年、目录资格或研究参与容易被直接解释为公平 | 要求识别具体获取、供应、负担或药品临床管理关系；人群和目录名称本身不构成 F |
| 供应内容按当前保障命题判断 | “加强供应管理”位于 F 的真实边界，容易被机械地全收或全排 | 依据对象、谓词及其与基本用药保障的关系判断；不得因缺少量化或具体药名自动排除，也不能只看“供应”一词 |
| E 与 I 明确解耦 | 临床获益容易被误作创新资格，或因缺少创新表达而漏掉 E | E 只看效果/获益命题；I 另看创新属性、支持或资格，二者分别判断 |
| I/F 的 0 须解释实际命题或相近边界 | 固定“未涉及本维度”模板掩盖模型是否真正处理了当前命题；反过来强求“最近边界”也会诱导编造 | 有相近概念时解释排除边界；完全无相近概念时说明当前命题实际涉及何事以及没有形成 I/F 命题 |
| 正类使用具体连续引文，长段避免整段复制 | 整句或整段证据虽可通过字面校验，却不能证明依据定位准确 | 每个 1 绑定当前单元中的最短完整证据；依赖上下文时另列承接证据 |
| 材料完整性与最终二元发布分离 | 旧版把“待定”混入发布标签，补料后仍可能沿用旧判断 | 缺料先退出并补全；最终 Schema 只接受 0/1，问题状态另列 |
| 代码只做结构和逐字校验 | 结构通过曾被误读为逐条语义质量已验证 | 验证器明确声明无法证明阅读、语义正确、理由专属性、证据充分性或背景传播控制 |

最终输出的 `execution_version` 固定为 `LLM-binary-v29`；采用同目录二元Schema。
