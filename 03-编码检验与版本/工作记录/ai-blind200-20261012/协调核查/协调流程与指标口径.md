# 200条双AI盲评协调流程与指标口径

本文件只准备配对、封存核查与统计口径，不进行语义编码，不读取两侧未封存答案。当前200条是已授权执行的工作量；不预先称其足以支持五维精度，也不自动扩样。原交付清单中“200待确认”的文字属于2026-10-10准备阶段历史状态。

## 配对已核实

两侧确为同一200个source_id，每侧各有200个唯一盲号、1000个维度判断。A/B材料JSON逐条原字节相同，材料内部source_record.id与协调映射全部一致。两份次序不同，只有3个位置碰巧对应同一条。因此必须用 **A_blind_id → source_id ← B_blind_id** 配对，不能用行号、序号或盲号末尾数字。

核查依据为原封存draw-and-mapping.json（SHA-256：5690672e10612371def277f7d98ed332e22cb281cfb5b636a9cbc93eaba1bd55），并复核pre-draw-freeze.json、无答案workbook-input.json、双方手册与执行说明哈希。无答案核查结果在“映射核对/mapping-check.json”；配对表在“映射核对/paired-mapping.csv”，仅供协调使用，不发给独立判读者。

实际为41层的两阶段等概率子抽样：先前800概率样本每层内按固定名额无放回抽至200；合成后每条纳入概率为n_h/N_h，权重N_h/n_h。权重合计4481。剩余池120/1444，历史曝光池80/3037；部门为NHC 29、NHSA 83、NMPA 88。两个域分别报告；合并加权仅描述固定4481语料审计，不能称全部材料未见泛化。不能沿用原800版权重；辅助层名不是真人标签。权重Kish有效N约136.11只诊断权重不均衡，不表示五维精度、效度或稀有正类数充分。

## 封存后运行

两侧都须先写完judgments.jsonl，再写submission.json。后者须明确status="sealed"、identity="AI评审A"或"AI评审B"、record_count=200、judgment_count=1000、independent=true、human_judgments=false、null_count，以及judgments_sha256、manual_sha256、execution_prompt_sha256。提交后任何修改另存新版本；不能修改独立首判原件。

每行格式为`{blind_id, judgments:{S:{value,evidence,context,reason},E:{...},Ec:{...},I:{...},F:{...}}}`。value仅接受JSON整数0、1或null；不接受字符串、布尔值、浮点数等隐式转换。null必须有具体理由，机械检查只能判断理由是否填写，不能确认其内容正确。

主线程在双方封存后运行（将A目录/B目录替换为实际目录，输出目录须为空且在输入目录外）：

```sh
python3 '/PROJECT_ROOT/outputs/ai-blind200-20261012/协调核查/check_sealed_blind200.py' audit \
  --a '/绝对路径/A目录' \
  --b '/绝对路径/B目录' \
  --out '/绝对路径/新的协调结果目录'
```

脚本不修改任何输入，不制作XLSX。先核验映射和两侧封存元数据，再读取固定答案字节核对哈希；只有两侧全部过关才解析答案。不读取机器参照或真人judge。输出JSON、CSV和Markdown，覆盖：缺失/重复/非法标签；逐维正、负、null及有理由待定；完整0/1/null交叉表和额外无效状态；双可判分母；原始及设计加权一致率、κ、正负类一致率；同一组分域结果；分歧/待定清单及双方原理由。重复ID不挑一行使用，而将该ID五维记为duplicate。

“有理由待定”是null的子集，不能与null相加。执行缺失、非法输出、null也不能混为一个状态。各维独立保留分母，某条I待定不删去其其他可判维度。机械通过不表示引文、理由或分类正确。分歧表仅供封存后协调，真人judge独立提交封存前不应看到AI判断或分歧。

## 现阶段与真人回收后能计算什么

|阶段/指标|需要的分母与条件|解释范围|
|---|---|---|
|现阶段A/B逐维正负/null数|各侧每维固定200条；分开列缺失和非法数|AI输出分布，不能称真实正负例数|
|A/B一致率Po、κ、正负类一致率|每维双方均为0/1的交叉四格；原始n与加权分母同时报告|AI–AI一致性，不是准确性或真人信度|
|真人judge回收后的正负例数|真人在该维有效0/1、null及失访/输出问题分别列明|先核验身份、独立性、材料版本；不以AI补真人空白|
|各AI对真人Precision|TP/(TP+FP)，分母为该AI预测正且真人可判的配对|需可信、绑定版本的真人参照；此分母不是总200|
|各AI对真人Recall|TP/(TP+FN)，分母为真人正且该AI可判的配对|重点报告逐维真人正例数；没有正例时NA|
|各AI对真人F1、κ|F1=2TP/(2TP+FP+FN)；κ需要完整配对四格及双方边际|全无正例可能未定义；NA不能改成1或判通过|
|Specificity、NPV|TN/(FP+TN)、TN/(FN+TN)|只是诊断指标，不能机械附加0.80目标|
|真人—真人κ|需两位真人协商前、相同材料的独立首判|只有一位真人judge时不能计算，也不能用AI顶替第二人|
|原项目整体机器验收|需原冻结方法的预测、相应可信真人裁定、身份/版本/完整样本绑定|本轮AI评审身份不自动等同原生产机器方法；不能据AI一致性宣称完成|

四格方向：A/B比较以A为行、B为列，a=A1B1、b=A1B0、c=A0B1、d=A0B0，双方都不当真值。对真人参照时以AI/机器为行、真人参照为列，a=TP、b=FP、c=FN、d=TN。Po=(a+d)/n；Pe=((a+b)(a+c)+(c+d)(b+d))/n²；κ=(Po−Pe)/(1−Pe)。正类一致=2a/(2a+b+c)，负类一致=2d/(2d+b+c)。设计加权是用原纳入权重求四格总数，不是有序类别的weighted κ。

零分母/Pe=1记NA并说明。保留完整3×3含null表；四格仅描述双方可判子域。未知记录权重不丢弃，另报未知率；不能简单剔除再归一化，宣称仍代表全1444/4481域性能。需要全域结论时还应计算未知的保守识别界，识别界不等同95%抽样区间。

## 区间与信息量检查

沿用原契约：41层分层SRSWOR的Rao-Wu重缩放bootstrap，5000次、seed=20261010，有限总体修正；全部五维、两个域和部门共用同一套重复权重。每层复抽n_h−1次，权重乘子为`1−sqrt(1−f_h)+sqrt(1−f_h)·n_h/(n_h−1)·k_hi`；全取层固定权重。层名、层内source_id排序；百分位采用排序后线性插值。脚本同时保存重复权重序列的SHA-256，便于复算。

脚本为加权Po和κ输出逐指标95%区间及宽度；不声称多维同时95%。未定义重复比例另报，若存在未定义重复，则仅给定义重复的条件分位数诊断，不标作无条件95%区间。退化[1,1]不能证明没有罕见错误。全部可判且零分歧时，脚本另给Po的一侧保守有限总体保护界：逐层反演零事件超几何概率、Bonferroni分配0.05/H，再汇总；该界不替代主区间，也不是κ或真人效度的边界。一般稀疏四格/未知联合界尚未实现，须真人参照阶段按原契约处理。

真人judge回收并封存后，才能依同设计为各AI/机器对真人的κ、P/R/F1计算区间、检查实际正负例与有效分母，再判断哪些维度信息不足。不能把A/B正例数或其区间宽度当真人效度信息量。信息不足时先指出具体维度、分母及区间问题；如需补充，另定有依据的概率抽样及分析计划，保留本轮结果，不自动挑争议/错例补到达标。样本若用于修订手册或提示，须登记相应ID/family转开发，不能继续称未见验证。

## 既有要求与方法来源

共同manual.txt规定五维概念、0/1/null、独立首判与版本保留，没有在该文件另列数值精度阈值。原项目要求见下列既存文件：真人独立首判逐维κ≥0.80；每机器相对可信裁定逐维κ/P/R/F1≥0.80。点值要求与区间精度分开，未增加CI下界或半宽达标线。本轮不新造阈值。早期规划中的半宽工作目标是建议性规划，不应据此追加隐藏验收条件。

- `/PROJECT_ROOT/outputs/goal-calibration-20261010/02-methods/prospective-statistical-contract-v2/validation-design-v2.json`：required_metric_matrix、formula_contract、confidence_intervals。
- 同目录`统计契约说明与勘误.md`：主区间、Specificity/NPV分母勘误、0.80点值与区间要求区分。
- `/PROJECT_ROOT/outputs/goal-calibration-20261010/02-methods/unknown-and-denominator-policy.json`：null、无效输出、可判子域、阈值及识别界。
- 200条包的`coordinator-private/pre-draw-freeze.json`及`draw-and-mapping.json`：实际层数、样本、概率、权重与两域范围。

脚本自检只使用合成数据，检查非法布尔/浮点标签、重复ID、null保留、四格方向、退化/未定义指标，并枚举n=2与n=3的全部小样本复抽，验证层总权重和FPC方差。另运行5000次合成复抽检查，记录见“脚本合成核查.json”。准备阶段未运行真实答案核查；主线程负责封存后执行与整合。
