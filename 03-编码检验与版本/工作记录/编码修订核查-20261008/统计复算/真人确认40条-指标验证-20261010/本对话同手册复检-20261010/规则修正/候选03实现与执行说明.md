# 候选03实现与执行说明

## 定位和范围

`dc26-relation-candidate-03` 是看过候选02冻结评估差异后的继续开发候选，不是盲规则开发或独立验证。它只消费四批无答案输入中的 `current_text` 和 `contexts`；预测阶段没有读取真人参照、旧预测或外部来源，没有按 `material_id`、部门、文件名设标签，也没有恢复旧证据。未运行4480条全量，未修改共同手册、原runtime、原输出或参照。

候选03以完整保留的 `relation_coder_v02.py` 为基础，只覆盖F模块的两个通用关系边界。S、E、Ec、I逻辑没有修改。

## 两项修正

1. 普通商保保障范围或支付管理不再自动进入F。只有当前文本或提供语境明确连接患者需要、支付能力、获取机会差异、持续治疗障碍或保障缺口时，商保安排才进入F。普通支付安排仍可按手册进入Ec。
2. 同一当前单元同时明示实际供应或治疗选项缺口对象、具体优先审评审批措施和程序制定动作时，进入F。泛称促进可及或支持创新并制定程序，没有缺口对象与针对措施关系时仍为F=0；不能以“为”“制定”“目的”等单词机械排除。

I逻辑保持候选02边界：只有实质创新分类条件与差异权利、制度使用或明确承接关系才进入I；单独身份或“按1类申报”不自动进入I。

## 执行入口和留痕

候选03规则入口是 `relation_coder_v03.py` 的 `code_unit({"current_text": ..., "contexts": [...]})`。批量入口是 `run_candidate_v03.py`：

```bash
python3 -B run_candidate_v03.py controls
python3 -B run_candidate_v03.py predict
```

runner禁止覆盖同名实际运行产物，因此以上命令用于新的隔离副本或在保留当前产物后复现；当前目录中的控制、预测和执行记录已经是实际运行结果。冻结后评估入口为 `evaluate_frozen_prediction_v03.py`，其现有输出同样禁止覆盖。

所有代码、控制、输出、执行记录和评估哈希集中记录在 `版本存档核查.json`。
