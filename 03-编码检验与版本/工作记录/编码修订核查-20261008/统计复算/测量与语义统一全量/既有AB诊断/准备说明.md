# 新规则／LLM 对既有 A-B 诊断准备说明

## 当前状态

本目录仅准备诊断脚本，尚未生成任何点估计或区间。准备时新规则 4480 条输出已存在；新 LLM 的 `all_predictions.jsonl` 和 `execution_summary.json` 尚未完成，因此脚本默认只做预检并报告等待，不会把部分批次当作全量结果。

既有参照继续使用已采用绑定中的 A 与 C；成品显示名将 C 改为 B，并明确记录 `C displayed as B`。它们只是共同手册变更后的诊断比较对象，不构成新手册下的新独立真人参照或新验证。

## 文件与运行方式

- 脚本：`diagnose_new_methods_against_existing_AB.py`
- 安全预检：`python3 diagnose_new_methods_against_existing_AB.py --mode preflight`
- LLM 全量完成并经 root 核查后执行：`python3 diagnose_new_methods_against_existing_AB.py --mode execute`

`execute` 固定生成：

- `新规则LLM-既有AB诊断-点估计与5000次区间.json`
- `新规则LLM-既有AB诊断-指标长表.csv`
- `新规则LLM-既有AB诊断-执行清单.json`

## 完整性与绑定门槛

脚本硬锁以下现有输入：新规则输入、规则全量输出、当前手册、LLM 冻结输入、提示、schema、validator、runner、run plan，以及旧 `actual_bindings01.json` 和旧比较脚本。旧绑定内部的 A、C、概率/挑战抽样设计、部门元数据和 `statistical_core_r3.py` 仍逐项按其既有 SHA 校验。

新 LLM 输出事先无法硬编码 SHA，因此必须由完整 `execution_summary.json` 动态绑定。脚本要求：

- `status=complete_actual_calls_structurally_valid`；
- `n=4480`，accepted、recorded、expected batch 数全部等于冻结计划；
- 选中尝试工具事件数为 0，选择不基于标签或指标；
- 冻结输入、提示、run plan SHA 与当前锁定文件一致，来源运行期间未变化；
- `execution_summary.output_sha256` 与实际 `all_predictions.jsonl` 完全一致；
- 输出 ID 与冻结输入 4480 条逐条同序，标签字段形状合法。

此外，脚本逐条确认规则输入与 LLM 冻结输入的当前文本相同；规则输出绑定当前手册和当前文本 SHA；旧样本 240 个 ID 全部存在于新 4480 语料；抽样文本 SHA、部门、概率样本权重和纳入概率均与旧设计一致；旧 A/B 参照的有效标注文本 SHA 与抽样记录一致。

## 统计设计

比较共五组：新规则—旧 A、新规则—旧 B、新 LLM—旧 A、新 LLM—旧 B、旧 A—旧 B。旧 A—B 的 P/R/F1 以 A 为左侧、B 为右侧参照，方向会在输出中明确；κ为对称指标。

概率 180 与挑战 60 始终分开：

- 概率 180：总体及 NMPA、NHSA、NHC，沿用 `N_h/60` 权重和旧 `department_unit_rescaled_SRSWOR` 5000 次设计区间；
- 挑战 60：总体及实际存在的 NMPA、NHSA，使用不加权点估计和旧 `department_unit_conditional_WR` 5000 次条件区间；不虚构 NHC 挑战组。

每一比较、部门和维度分别输出 11、10、01、00 四格及 κ、precision、recall、F1。`None`/unknown 只在该维度该比较中 pairwise 排除，保存数量和 ID，绝不替换为 0。零分母由数学核返回 `None`，CSV 显示 `NA`。

脚本只调用既有数学核的 `cells`、`metrics`、`interval`、`replicate_factors`、`weighting` 和 `safe`。不调用 `load_context`，不读取旧机器输出，也不读取旧比较脚本生成的历史结果作为新机器结果。

5000 次区间只反映旧抽样设计或挑战样本的条件重抽样，条件于固定标签、材料和参照；不覆盖共同手册兼容性、语义真值、参照陈旧或来源完整性的不确定性。
