# 共用定义试编码运输与校验复制说明

技术来源为 `候选09-分步判读/runtime/` 下的 `run_production_v32.py`、`validate_binary_output.py` 和 `output_schema_codex_compatible.json`，原件未修改。未复制或读取旧标签、结果、指标、人工初稿或保护池；没有运行模型。

- 三处协议常量同步为 `COMMON-5D-20261009`、`LLM-common-definition-pilot`、`development_labels`；runner计划中的method_version及汇总输出也同步。
- F子型替换为 `needs_based_guarantee`、`patient_affordability`、`opportunity_barrier`、`equity_evaluation`。沿用F=1至少一种、F=0为空及不重复约束。
- I子型和S的安全质量依据原样保留。
- 每行新增必填布尔字段 `quality_content_without_safety`。S=1时必须false；S=0时可true或false。该字段只记录质量内容，不产生S标签。
- 校验仍只涉及字段、类型、版本、ID顺序、逐字引用、子型及明确逻辑关系，不按语义、指标或分数验收。
- `run_attempt`的CLI运输、输入与事件留痕、逐字证据核查、零工具事件拒收、事件输出绑定，以及`main`的首次技术合格attempt选择均保留。离线测试对整个runner进行AST比对，唯一允许的变化是上述三个版本字符串。

`offline_structure_tests.py`只使用构造记录检查有效记录、错误版本、伪造引文、F=0带子型、工具事件及新增布尔约束，并检查schema字段契约。测试会阻断subprocess.run，不调用main、run_attempt或CLI；不做语义评测。当前未安装jsonschema，故未声称运行JSON Schema引擎验证。测试实际结果见 `offline_test_result.json`。

提示词与试编码计划由root另备；此处未创建。runner沿用原默认提示词文件名，使用时须显式传入正确的 `--prompt`。运输文件保留来源文件名以便对照，不代表继续使用旧语义协议。
