## 后续运行接口

在 600 条独立提交完成后，由主任务启动一次新的 artifact 创建操作；默认生成两份 xlsx。沿用已安装的 artifact-tool 与 bundled Node：

```bash
'/LOCAL_HOME/.cache/codex-runtimes/codex-primary-runtime/dependencies/node/bin/node' \
  '/PROJECT_ROOT/outputs/validation-expansion-20260926/build_reviews.mjs' --formal
```

`--formal A` 或 `--formal C` 只生成指定评审者，但该评审者仍必须有完整 24 批、600 条提交。默认无 `--formal` 时保留原 60 条模式及原名称；已有目标 xlsx 时停止，防止误覆盖已经完成的 60 条成果。

正式输出为：

- `正式盲评600-A-AI评审.xlsx`
- `正式盲评600-C-AI评审.xlsx`

三张工作表仍为“独立盲评”“原文语境”“共同手册”。正式检查文件和预览使用 `formal600-A-...` / `formal600-C-...` 前缀，不占用原 60 条的任何文件名。目标或对应检查/预览已经存在时拒绝覆盖；xlsx 使用独占 partial 文件及不覆盖目标的原子 hard-link 发布。中途失败不自动删除既有文件或半成品。

## 运行前置检查

正式模式读取最终冻结清单、H600 封存信息，以及所选 A/C 的手册、`材料-01.json` 至 `材料-24.json`、`结果-01.json` 至 `结果-24.json`。创建首个工作簿前，先检查所有所选评审者：

1. 发布状态与 600 条样本量正确，冻结清单哈希、材料和共同手册哈希一致。
2. 材料及结果各恰有 24 批、每批 25 条；批次顺序、版本、coder、协议确认及 `input_packet_sha256` 匹配。
3. 每批结果 ID 与对应材料完全一致；全体恰为 600 个唯一 ID，不按结果行顺序拼接，不补标签或占位结果。
4. 五维标签和理由完整，F/I 子类型、S 质量依据、材料状态及证据格式按现有提交契约校验；材料充分时仍允许个别概念待定。
5. 预估所有正文、语境和手册行高。任何一行超过 409 时报告具体位置并停止，不截断、不缩小字体或自动丢弃内容。正式运行仍需查看渲染图确认实际排版。

所选 A/C 均生成时，另校验两套手册及 24 个材料包逐字节一致。构建后、写文件前重新核对输入哈希及批次清单，防止构建期间输入变化。

## 内容保留与显示

“独立盲评”保留完整分析单元、五维原始标签、逐维理由、证据、综合说明、材料问题、材料核验和子类型/质量标记，B 列宽沿用原版。

“原文语境”按字段路径递归展示材料及原始独立提交的全部字段，包括来源/页码、`verified_supplemental_context` 内的嵌套 `contexts`、`content_role`、`content_role_basis` 和核验元数据。空数组、空对象、null 和原有空字符串均有相应字段记录；不再使用只挑 `.text` 的旧显示方式。长文本按 Unicode 字符及换行分块，块序号可见，按序拼接可复原原字符串。JSON Pointer 中 `/`、`~` 的转义只用于字段路径，不改文本值。

“共同手册”按顺序分块保留完整冻结协议，不修订或摘要协议。原始 JSON 和手册文件始终只读。工作簿仅是独立提交的呈现，不产生新裁定，也不调用统计程序。
