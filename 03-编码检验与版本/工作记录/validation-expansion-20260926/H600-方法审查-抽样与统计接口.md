## 2. 已满足的程序条件

- `allocate()` 在合法正整数层规模下实行比例初配、最小 `min(2,N_h)`、总体上限及确定性余数调整；无法满足层下限时停止，不临时自行合并年份。用固定合成种子生成 10,000 组配置，其中 9,577 组可行配置均满足总量、层下限、层上限及输入字典顺序不影响结果；423 组下限不可行配置均被拒绝。合法小总体能够全取。
- `sample_holdout.py:76–78` 按层名和稳定 ID 排序，以固定种子 `2026092602` 层内无放回抽样；随后打乱展示顺序不改变包含概率。权重 `N_h/n_h` 与统计模块完全一致。层内个体抽样的设计成立时，同一文档中存在多个分析单元并不自动把本设计变成文档整群抽样；适用范围仍是固定单元池。
- 正式抽样要求冻结状态及文件哈希；已有 `H600` 目录时拒绝再次抽样，`mkdir()` 也不允许覆盖。这是有效的常规重抽保护，但不等于能够证明目录从未被人为删除或改名。
- 抽样程序自身没有按照材料是否容易判断进行筛选。统计模块要求全部样本及层清单存在，待定保留在 3×3 表、覆盖率和未判边界中；不把待定自动当作 0，也不把 A/C 一致自动生成为参考真值。
- `survey_metrics.prepare()` 拒绝重复样本 ID、层数目不符、层规模不符及非普查层 `n_h=1`，并重新由 `N_h/n_h` 计算权重。
- 统计公式使用层内 `n_h−1` 次均匀重抽，乘数为 `1+sqrt(1−n_h/N_h)×(n_h*m_i/(n_h−1)−1)`；每次层权重总量仍为 `N_h`，线性层均值的条件方差为 `(1−f_h)s_h²/n_h`。普查层固定权重 1、抽样方差 0。此代数匹配支持线性设计方差，不证明非线性 κ、PRF 或稀有分母的精确区间覆盖。

## 3. 正式发放前的必要修复

### 3.1 盲材料只限制了外层字段，嵌套字段会原样透传

位置：`sample_holdout.py:80–86`。

`input_assessment` 整个对象被复制；白名单中的 context 值也未经内部结构筛选。以 AST 提取实际盲包构造表达式执行合成输入，`input_assessment.labels` 和 `verified_parent_context.prior_coder_answer` 均原样出现在输出。因此，“外层只挑了几个字段”不能证明无答案包。

必要修复：采用一个可独立测试的材料构造函数，明确允许的文本、页码、来源和核验语境结构；对嵌套对象递归限制键及值类型。结构性缺失标记可以保留，但原有评审答案、维度判断、机器输出、旧评审理由和提示性结论不能透传。若暂时无法证明 `input_assessment` 的内部语义安全，输出固定的结构性状态字段或省略该对象。不得通过删除缺文本/缺语境单元解决问题。

验收使用合成嵌套旧答案字段，确认被拒绝或剥离，同时正文、合法语境及缺失标记保留。不要仅对政策原文搜索单字维度名来判泄漏；那会误伤正常政策内容。字段白名单须与实际输出 schema 一致并冻结。

### 3.2 年份的优先顺序正确，但“已核验”与合法年份未被校验

位置：`sample_holdout.py:33–39`；方案第 22 行。

代码只判断字段真值。合成 `component_year='unknown'` 会覆盖有效发布日期，并被记为 `verified_component_year`；合成 `publication_date='not-a-date'` 会产生年份 `not-`，却标为 `verified_publication_date`。这些是实际执行得到的程序反例，不是对真实元数据的断言。

必要修复：冻结年份字段的契约并在抽样前验证。只有明确核验的合法组件年份才能优先，只有合法且明确核验的发布日期才能进入第二顺位。可以校验独立核验状态/证据字段，也可以使用已冻结且保证这些字段仅存放核验值的 schema 和预检记录；不能仅凭非空就称 verified。资料标示年单列依据，无可用年份进入 `unknown`。未知或非法值须按预定规则处理，不能临时据抽样结果修年。

### 3.3 构建抽样框前缺少唯一键及部门映射一致性校验

位置：`sample_holdout.py:25–29,32,40–42`。

三个字典推导会静默覆盖重复的分析单元 `review_id`、接入文档 `id` 和分类文件 stem；`set()` 会默默去重候选 ID。合成重复 `review_id` 的最后一条覆盖了前一条，并改变分层年份。候选 ID 是否属于语料虽有检查，但不足以防止这些碰撞。

必要修复：在转字典/集合前拒绝重复键和重复候选 ID；验证每个分析单元恰好连接一条文档元数据和一条分类元数据；检查非空候选池。`allocate({},600)` 当前返回空字典，正式 H600 应明确拒绝空框。

部门层目前来自 `adapter.documents[].group`，而分类表只被用于文件名年份。两个来源均被哈希并不能证明它们的部门映射相同。正式预检应明确哪个字段是冻结研究部门系统的权威映射，并验证接入表与之逐文档一致；主比较单次归组、中央 GOV 单列。无需、也不应临时改成按第一署名部门归组。

### 3.4 冻结校验还没有完整绑定程序及发布过程

位置：`sample_holdout.py:57–63,87–97`。

1. 必需冻结项未包含抽样程序、统计程序或输出材料 schema。现在即使程序改变，已有数据文件哈希仍可能通过。至少应绑定实际执行的 `sample_holdout.py`、`survey_metrics.py`、共同手册、输入/语境规范及适用的预测实现/解析规范；若其中内容已合并在某文件，可明确绑定该文件，无需人为增加重复文档。实际使用的 LLM 提示和运行方式也应按方案冻结；不运行该比较列则如实记录不适用。
2. 冻结清单先读为对象，稍后又从磁盘求其哈希；没有验证清单本身在两次操作之间不变。应对初始清单字节取哈希、据该快照执行，并在发布前验证仍一致。
3. 文件末次哈希检查发生在 A/C 材料已写入后。失败会报错但保留可见材料，且研究者清单已经标为 `drawn`。应先写隔离暂存区，在所有校验通过后才发布；或使用明确的未放行标记，并要求下游只接受通过封存验证的目录。失败产物不得交给编码员，也不得为了结果重抽。
4. 封存信息应绑定实际材料文件和手册的哈希，验收 A/C 手册与对应材料逐字节一致。当前两个输出包使用同一内存材料，设计上应一致，但最终文件没有被哈希绑定，发布校验仍有缺口。

这不是要求对任意恶意文件系统攻击建立防护；所需的是让普通版本变更、半途失败和误发包能被明确发现。

### 3.5 默认预览仍指向补充 v2，不能充当最终抽样依据

位置：`sample_holdout.py:64–73`。

不带 `--draw` 的路径硬编码 `开发暴露映射-补充v2.json`，输出状态也明确为未抽样。无论已有预览里面显示多少条，都不能据此称正式 H600 已抽取，也不能把其层规模直接交给最终统计。正式 `--draw` 使用冻结清单路径，故这不代表正式路径必然也用 v2；需要验收冻结清单实际绑定的是完成 D60/已知开发及近重复排除后的最终版本。

必要处理：预览明确绑定所用输入哈希及“未抽样”状态，最终分配由最终冻结池重新计算；旧预览只保留为历史计划。核对暴露映射确由同一冻结语料、开发登记和预定重复规则生成，不能只验证它自身文件未变。U* 大小以这次核对后的有限池为准，不默认采用历史暂定数字。

## 4. 抽样清单到统计接口的最低连接契约

两个文件目前不是直接相接的完整流水线。抽样清单的 `plan.strata` 是字典，统计模块要求层对象列表；抽样清单还未包含评级列。这是需要补齐的接口，不是统计模块会自行恢复的信息。

| 统计输入 | 唯一允许的数据来源/验收 |
| --- | --- |
| `strata` | 从正式封存的 `plan.strata` 转为 `{stratum,N_h,n_h}` 列表，全部层保留 |
| `population_N` | 正式 `plan.N_star`，并等于所有 `N_h` 之和 |
| `rows[].id` | 正式盲 ID；集合必须与抽样清单完全相等，不按行号连接 |
| `rows[].stratum,N_h,n_h` | 正式研究者映射，逐 ID 精确一致，不由标签重新分层 |
| `A`、`C` | 独立原始提交逐 ID 连接，每条恰有 S/E/Ec/I/F 五维 |
| 可选 `dictionary` | 用研究者映射的原始 `review_id` 连接已封存预测，再转回盲 ID；不得按展示顺序拼接 |
| 可选 `reference` | 另行明确记录的参考裁定及来源；不由程序根据一致、多数票或机器结果自动制造 |
| `reference_info`、`dictionary_info` | 明示 AI/真人等实际来源及已冻结预测版本；正式包装层另绑定对应文件哈希 |

统计模块内部会再次检查唯一 ID、层行数及权重，仍不能发现“把错误标签恰好配给另一个同层 ID”或“给了一个内部自洽但不完整的总体层清单”。连接程序必须先验收完整 ID 集合及固定层信息。

正式包装层还须硬性要求 `sample_size_matches_H600_plan is True`。统计工具为合成 QA 和其他合法设计保留通用接口，当前该字段仅是诊断，不会因为少于 H600 计划样本量自动报错。

待定及行政缺交必须区别：真实编码员提交的“待定”保留原样；缺整条提交、缺维度或解析失败不能悄悄改成 0。若按既定规则将缺交编码为待定以保留分母，须同时留存“未提交/解析失败”等来源状态，不能声称编码员实际做出了待定判断。未齐交时也可只形成明确标注的过程诊断，不能当作完成的独立评审结果。

本次合成接口检查使用一个非普查层 `N_h=10,n_h=2` 及一个单元普查层：权重为 5、5、1；2000 次重抽的层权重总量分别固定为 10 和 1，普查层权重恒为 1；一条待定仍存在于原始和加权表，可评覆盖为 10/11。仅有 A/C 时 `reference_generated=False`，没有输出分类器对参考的验证。

## 5. 统计解释的放行边界

- 条件二元四格、κ、正负一致率和 PRF 针对双方均可判部分；全样本覆盖和未判边界必须同时报告。二元补全边界是固定已判标签下的加权样本识别范围，不是置信区间，也不是参考真值。
- 2000 次固定种子的百分位区间为逐指标、逐维近似 95% 区间，不是五维同时覆盖；超过 10% 重复无定义时抑制区间。Rao–Wu 重缩放权重保持正值，已观察稀有类别不会因该重抽而完全消失，因此“无定义比例低”不证明稀有召回/κ 区间稳定。
- 普查层抽样方差为 0 不表示编码、共同 AI 偏差或参考错误为 0。所有推断只对应最终 U*；不扩大为原 4924 单元、从未读过原文、未来政策或真人专家有效性。
- 小层下限已经无法满足时程序应停止。当前方案只写“既定同部门相邻年份规则”，若没有另外冻结的确定性合并规则，就不能在看到配置或标签后临时选择有利合并；若实际无需合并，则保留原层即可。

## 6. 一次性正式审核条件

下列条件全部通过后才发放 H600，不需要循环追加新的方法研究：

1. **输入冻结完成**：D60 开发结束；最终候选池及所有必需输入/程序/材料规范已绑定哈希。最终 U*、纳入排除数与来源版本一致；没有以难判或缺语境作为静默删样理由。旧 v2 预览仅作历史资料。
2. **抽样框预检通过**：分析单元及连接键唯一，候选 ID 无重复且全部可定位，部门映射一致，年份合法且依据分类正确，候选池非空。实际所需层下限可满足；若确需合并，先执行已经固定的合并规则。
3. **纯合成边界测试通过**：嵌套旧答案不会进入盲包；非法/未核年份不冒充已核；重复 ID 被拒绝；缺语境保留单元；分配总量与层下限/普查检查通过。不得用真实 H600 标签调试这些规则。
4. **只正式抽取一次并封存**：`n=min(600,N*)`；抽中 ID 唯一，逐层实际数等于 `n_h`；记录概率、权重及未抽中 ID；初始与结束冻结快照一致；A/C 同版手册和同一无答案材料核验通过；所有正式产物有哈希。失败或半成品明确隔离，已有目录不被覆盖重抽。
5. **标签揭示顺序受控**：机器预测在参考标签揭示前封存；A/C 隔离完成并保存原始提交，之后再进行争议复核。抽样 ID、参考标签及评估表现不用于继续选择词典/提示版本。
6. **统计连接通过**：正式映射、A/C 原始提交及可选预测/参考按 ID 一一连接；完整抽中 ID 集合和所有层保持不变；缺交、待定及解析失败透明记录；统计样本量符合计划，`sum(N_h)=N*`，逐维覆盖、四格及限制与区间一起输出。

本报告只写入本文件；未修改抽样程序、统计程序、方案或任何真实数据。

递归字段投影通过不等于自由文本已经过语义安全认证。`reason`、`note`、`usage` 等允许字段只能承载已冻结的结构性说明或核验来源，不得借这些值携带先前维度判断；正式预检应确认其生成来源。这里没有建议对真实政策全文做武断的答案关键词过滤。

部门来源一致性、年份核验依据、开发及近重复排除完整性仍属于真实冻结资料的验收项目，本次因盲性边界没有核查，也不声称这些资料存在错误。ID 连接桥尚未纳入本次授权阅读范围，仍以第 4 节契约验收。

冻结词典分别对 A 和 C 进行比较，在现有 `survey_metrics.py` 中可直接执行两次：

- 第一次 `reference` 明确取 A 的原始独立提交，`reference_info.kind='AI'`，description 写明“单独编码员 A 的原始标签；非协商裁定或无误真值”；输出命名清楚标注 dictionary_vs_A。
- 第二次 `reference` 明确取 C，来源描述和输出命名相应标注 dictionary_vs_C；保持同一批抽中 ID、权重、冻结词典预测及 A/C 原始列。

这两项对照应在揭示 H600 标签前固定，并同时报告，不能择取较高者作为词典表现。它们使用同一 H600，不能被视作 1,200 个独立样本或两个独立验证总体；使用相同随机种子的重抽也不改变这一点。每次调用本身仍会计算未修改的 A_vs_C 一致性，正式报告可保留一份首次独立结果。后续协商/第三方裁定如果发生，应另存版本、来源及待定，不覆盖原始 A/C；该参考比较作为另一个明确命名的分析。

上述做法不需要修改统计核心，也不等于将任一 AI 编码员认作金标准。
