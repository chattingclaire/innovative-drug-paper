## 1. 固定概率抽样与排除分割

- 固定阶段为 V600、预算 600、抽样种子 `2026092605`；冻结清单必须同时声明一致的阶段、预算、抽样种子及配对统计 bootstrap 种子 `2026092606`，类型和值都检查。
- 暴露清单必须由无重复的 `exclusions` 与 `provisional_eligible_ids` 构成既定分析 ID 的完整互斥分割。重叠、漏 ID、陈旧 ID、重复语料 ID 及重复 eligible ID 不允许静默进入抽样。非分析语境材料不被计入抽样总体。
- 使用实际冻结的 helper 字节执行既有部门/年份分层、分配和材料清理函数，不从当前工作区临时替换 helper 实现。沿用部门单次归属、年份优先级、比例分配及整数调整；小层可普查，非普查层至少 2 条。
- 层按名称排序、层内原始 ID 排序，再进行无放回抽样，最后用同一固定随机源打乱展示次序。反转输入语料顺序不会改变样本。预算为 `min(600,N)`，N 小于 600 时完整普查并记录实际数，不补入排除资料。
- 保存每层 `N_h,n_h,pi=n_h/N_h,weight=N_h/n_h`、原始 ID 到 V600 盲 ID 的映射、来源元数据、目标文本哈希与未抽中 ID。合成例验证固定数量、正确权重、已排除单元不入样和全取时权重为 1。

比例分层的代表范围仅为最终候选框。它不保证稀有维度有足够阳性，也不把五维标签格或两份评审当成独立样本数；抽样程序没有性能通过线。

## 2. 冻结、一次尝试及隔离发布

程序先读取冻结清单与所有登记文件的字节，逐项核对 SHA-256，再确认运行中的 sampler 与冻结 sampler 一致。机器预测文件作为不透明字节绑定，不在本程序中解析标签或用于抽样。`sample_helpers` 由已核对的快照字节编译执行；合成陷阱 helper 证明实际执行的是该快照，而不是另一个本地 helper。

初审时，一次尝试仅由输出目录及其 `.partial` 目录限制，换一个 destination 仍可能再次调用。修复后，在任何样本选择前，还会于冻结清单同目录以**完整冻结字节哈希**命名独占 attempt 登记。相同冻结内容改用另一 destination 时已被拒绝；失败后恢复输入，也不能借另一 destination 再次抽样。原 destination 或 `.partial` 存在同样拒绝。

发包先写入隔离目录。所有材料写完后，程序再次逐字节核对冻结清单及全部输入，核对 A/C 对应文件同字节，记录输出文件哈希，然后才更名发布。合成检查确认：

1. 抽样前输入哈希不符会拒绝进入选择。
2. 合成选择完成后输入发生变化，会保留 `.partial`、不发布正式目录。
3. 失败尝试不能通过改变 destination 重试。
4. 成功发布的映射、手册及材料均有输出哈希，A/C 材料同字节。

这是一项可追踪的一次尝试约束，不是防恶意复制整个环境、删除日志或改写冻结文件的安全系统。改变冻结内容会产生新哈希，其研究身份和既往暴露仍需研究登记管理，不能把另一个冻结版本冒称原版本未尝试过。

## 3. 原文、来源信息与答案过滤

主材料只输出盲 ID、完整 `unit_text`、`source_title=original_file_stem`、原样 `pages`、允许的语境、材料状态和共同语境说明；不向编码员暴露 `review_id`、抽样权重或机器标签。合成带空格/括号的来源名称和多页列表在输出中保持完整。

普通语境沿用冻结 helper 的递归白名单；嵌套 `labels`、`answer` 等额外字段被去除，材料状态仅保留允许的状态和来源说明字段。合成例同时覆盖了顶层答案、嵌套语境答案及 assessment 内答案过滤。重复 JSON 键、NaN 常量、重复 context field 和未批准的 context field 均拒绝。

白名单是结构控制，不是对所有自由文本的语义审查。源文、verification 或其他允许的说明字符串是否夹带解释性答案，仍须在最终材料/提示交接时保证；不能仅凭字段名过滤就宣称任意输入都绝无答案泄漏。保留真实政策标题和页码意味着评审仍不是来源机关盲。

## 4. verified_object_scope 契约

### 初审反例及修复

初版允许 `unit` 缺少 `source_sha256`、scope 的同名字段为 None 时通过相等检查。这没有形成有效源文件哈希绑定。修复后，source、target、quote 三个哈希均要求 64 位小写十六进制摘要，并进一步核对 scope 的 source 与 unit 相同、target 与实际 `unit_text` 字节相同、quote 与实际引文文本字节相同；空或非法源哈希的合成反例已被拒绝。

初版只校验抽中单元，未抽中候选存在 scope 而 `context_fields` 漏列该字段时可能放行。修复后在随机选择前遍历完整 corpus 的 scope 契约，包含未抽中分析单元与非分析语境记录。两个合成反例均在创建随机源之前被拒绝。scope 字段若出现但不是列表（例如 None），也会拒绝；空列表仅表示没有实际 scope 内容。

### 当前允许的证据结构

scope 保留精确字段集：`kind/source_sha256/unit_text_sha256/text/text_sha256/locator/verification/normalization`，不允许附加五维答案字段。支持以下 4 种冻结契约：

| kind | normalization | locator |
|---|---|---|
| drug_clinical_trial | none | article、line、source |
| drug_regulatory_research | remove_extraction_whitespace | physical_pages、source |
| anticancer_drug_development | remove_extraction_whitespace | physical_pages、source |
| anticancer_drug_safety_dossier | remove_extraction_whitespace | physical_pages、source |

文本条文的 article/line 必须为正整数，不能是布尔值；PDF 物理页列表非空、每页为正整数且不重复；source locator 必须为绝对路径。引文和 verification 必须是非空字符串。4 种合法 scope 均能无损写入 A/C 共同材料；错误 normalization、重复或布尔页码、额外标签、过期目标哈希及不一致来源哈希均被拒绝。

程序保留 normalization 与 locator，不自行重抽 PDF 或验证其引文位置。它核验的是**已提供证据与已提供 corpus 的绑定关系**，不是证明该引文真实来自指定页、实际适用于目标单元，或足以支持某个维度为 1。真实来源、引文规范化、适用范围和完整性由最终 PAPER 源文交接审查负责，不能把本次合成程序审查改写为该项源文核验已完成。
