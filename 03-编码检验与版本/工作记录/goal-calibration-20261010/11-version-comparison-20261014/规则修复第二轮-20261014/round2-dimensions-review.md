# 第二轮dimensions独立反例审查

只读审查第一轮与第二轮`code/dimensions.py`差异、`round2_dimensions_tests.py`，另构造18组用例比较两版。没有更改分类源码、现有保护用例或任何人工标签。运行证据在`round2-dimensions-review-probes.json`，包含两版dimensions/relations SHA、完整输入、预期和实际结果。

结论：新语义路径能补回真实支付、临床无效暴露、明确药物病例范围及综合审评标准，但目前有四类边界明显放宽。18组中第二轮通过8组，未通过10组；其中9组属于第二轮新增误判，另1组为原有手续排除仍未充分解决。不能用这些自拟测试计算独立验证得分，也不应为通过测试更改预期。

## 1. 高优先：支付执行检测跳过了“实际动作还是手续对象”

新`_economics`在原有内容过滤前直接对`结算/支付/报销…费用`与支付扩展表达`acc.add`。`_form_only`目前无法完整识别按钮、凭证、引用的栏目名称或操作培训，因此这些纯手续被当作费用责任。

以下四组原版Ec=0，第二轮Ec=1：

1. `药品目录管理系统仅要求上传结算医保费用的凭证，不审核其中的费用内容。`
2. `药品目录管理系统设置“结算医保费用”按钮，按钮名称不允许修改。`
3. `药品申报表增加“为创新药拓展更多支付空间”栏目名称，不评价具体支付内容。`
4. `药品目录工作组应组织学习“结算医保费用”系统操作步骤。`

均不应因名词修饰语中有“结算/支付”就赋Ec。直接正例`经办机构应及时支付医保药品费用`仍应为1。

最小修复建议：
- 在新支付分支加“当前主动作”判定：结算/支付必须是当前要求、许可、责任或明确记述的经济动作，不能仅修饰凭证/按钮/字段/栏目/操作步骤。
- 对引号内短语检查其外部谓词：设置/命名/上传/填写/学习/培训对象为形式容器时，不把容器名称当政策动作。
- 新路径不要在后续判断否定其内容性质后仍保留已`acc.add`的正判；先决定是否为实质关系，再增加标签。
- 不要以整条字符串包含“支付”就抵消形式排除；也不要将“上传凭证”一概排除：如果另有“应在30日内支付药费”等独立内容分支，后者仍成立。

## 2. 高优先：综合审评定义继承仅检查证书名，误收历史状态/手续

新`_review_condition_units`的进入条件为`综合/技术审评结论通过`，再检查“批准药品上市 **或出现药品注册证书**”。后者太宽，没有保证当前标准判断决定实质待遇。

以下原版S/E=0，第二轮均为1：

- `综合审评结论通过后，将药品注册证书编号录入系统。`
- `综合审评结论通过。本次仅办理药品注册证书签章。`

两例均配同源紧前`对药品的安全性、有效性进行综合审评`。前者将既有状态用作手续时点，后者两句甚至不构成同一条件—上市决定。当前手册禁止从已通过状态展开全部标准。

另单独探测同主体范围：

- 当前：`药品乙的综合审评结论通过的，批准药品上市。`
- 前段：`对药品甲的安全性、有效性进行综合审评。`
- 第二轮S/E仍为1，尽管前段明示的是另一药品。

最小修复建议：
- 删除“只要出现药品注册证书就能进入”的支路，改为明确`批准/不予批准…上市`或`发给/授予/撤销…药品注册证书`等实质后果；录入、签章、打印、编号不够。
- 条件与实质后果须在同一规范分支内，不能跨完整句号从“通过状态”捞取另句证书名称。
- 若定义和当前有明示对象限定，须对象一致；不能只要求同源、同组件、同名审评。泛指“对药品的…”可解释相同一般规范，特指药品甲不能解释药品乙。
- 真实正例`综合审评结论通过的，批准药品上市`仍可完整使用同名审评内容。

## 3. 高优先：病例适用范围忽略否定与排除对象

新增`_object`支路用`针对|适用于|面向…药物`匹配适用范围，未识别“不适用于”；也未检查当前已经明确医疗器械研究等其他对象。适用范围与`安全性资料`分散在同段不同分支也能拼接。

原版S=0、第二轮S=1的反例：

- 当前：`死亡病例的安全性总结报告应包括相关病例。`
- 同源source_paragraph：`本节不适用于药物临床试验；针对医疗器械研究的安全性资料另行规定。`

以及：

- 当前：`医疗器械研究死亡病例的安全性总结报告应包括所有病例。`
- scope：`针对药物临床试验的安全性资料整理制定本要求，不适用于医疗器械研究。`

最小修复建议：
- 对药物适用锚点检查否定范围；不能让“不适用于药物”命中“适用于药物”。
- 只连接同一scope分支中的适用对象与报告内容，不能跨分号借用。
- 当前有明确另一研究对象时拒绝以scope覆盖当前对象；记录其为不适用/对象冲突。
- 原正例“针对创新药规范安全性资料整理”＋死亡/SAE病例内容覆盖仍应为S=1。只有截止日期的报告上传应继续不获对象内容标签。

## 4. 中优先：无效暴露新路径将字段内容误作效果论述

反例：`给药方案数据库新增“减少患者的无效药物暴露”这一字段名称。`

原版E=0、第二轮E=1，basis=`avoid_ineffective_drug_exposure`。新支路只检查同条“给药方案”与“减少患者无效暴露”，没有判定前者是数据库名称、后者是被引用的字段名。

最小修复建议：新支路同样须通过形式/引用内容边界；明确治疗方案调整与患者无效治疗暴露的联系，而非任何共现。保护正例`优化给药方案，减少患者的无效药物暴露`；保留反例药代暴露水平、无效数据记录，以及字段名称。

## 5. 中优先：未提交报告排除的例外仍过宽（非新增回归）

`未提交药物安全性报告的，由行政部门分析迟交原因。`

两版都S=1。第二轮想排除未提交报告，但任意“评价/评估/分析”就解除排除；本例分析的是迟交原因而非药物安全内容。

最小修复建议：例外必须是针对药物安全性、风险证据、病例或内容缺失的评价分析，不能仅检查存在分析动词。保护“报告缺少严重不良反应病例分析，应补充”及混合句真实风险分支，不能误清空。

## 6. 现有round2_dimensions_tests.py漏测之处

已有正反例覆盖基础申报字段、其他来源/组件、不同审评名、病例纯截止时间和普通药代暴露，方向正确。未覆盖：

- 新支付路径中“动作短语被当凭证/按钮/栏目/培训内容”的嵌套范围。
- 综合审评通过**状态**＋证书手续，以及不同药物的同名审评。
- 同源scope里的否定适用、排除对象和跨分支拼接。
- 无效暴露短语作为字段名称。
- 手续分析动词与实质药物风险分析的区别。

建议补这些构造保护再回归277条，避免仅补对已知分歧却引入更广泛的新误判。本次未运行4481条。
