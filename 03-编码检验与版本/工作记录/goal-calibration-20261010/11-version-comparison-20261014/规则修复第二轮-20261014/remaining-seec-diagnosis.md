## 1. 仍有多少分歧

S：12项FN、1项FP、2项NULL；E：6项FN、2项NULL；Ec：3项FN、2项NULL。合计28项，涉及19条。NULL集中在00111、00123的同版优先审评条件解析中。不能将NULL计为0。

可优先处理的dimensions路径是：03214的医保费用结算、03714的明确药品支付扩展、04490的纯提交手续排除、00206的无效治疗暴露语义，以及在对象已建立时的01817病例内容范围。03526、04071等涉及药物试验风险的内容，必须与普通数据/行政风险分开。

## 2. 清晰、可通用修补的dimensions路径

### A. 04490：报告“是否提交”被误当实质安全内容

原文：`(三)申办者未按照要求提交研发期间安全性更新报告的;`

第一轮S=1，`general_evaluation_or_information`；`_generic`把“提交/报告”视为CONTENT_ACTION，而`_form_only`没有覆盖“未按照要求提交某报告”这种纯手续触发条件。父句是“有下列情形之一的，可以要求申办者调整药物临床试验方案、暂停或者终止药物临床试验”，也不能替这一个手续分支补入风险实质判断。

建议：识别否定/逾期/未按要求的**报告提交状态**，在当前分支没有评价、风险证据或内容核验时排除S；不要排除所有“提交安全性报告”。形式排除应在_generic和_safety_effect共同生效。

保护对：
- 反例：`未在规定时间提交安全性报告的，暂停药物临床试验。` → S=0。
- 正例：`安全性报告显示该药导致严重肝损伤，应暂停给药。` → S=1。
- 正例：`安全性报告应包括所有死亡病例和严重不良事件病例的分析。` → S=1。
- 混合例：`未按时提交报告，或者报告提示新的严重药物风险的，应暂停试验。` → S=1，但仅风险分支贡献。

### B. 03214：明确医保费用支付责任漏Ec

原文含：`统筹地区医疗保障部门负责《药品目录》及相关政策的实施……按规定及时结算和支付医保费用……`

第一轮Ec=0，理由“只有谈判阶段、普通申报身份或未展开的协议/经济名称”。对象已明确，问题在_economics末层`substantive_content`未覆盖“医保费用”，关系词表又缺“结算/支付”对费用的直接作用。

建议：补明确药品用药背景下的`结算/支付/清偿`＋`医保费用/药品费用/治疗费用`关系，允许定性责任，不要求金额。避免把任意“支付费用”放宽到办公、设备、科研经费。此例句内已经给出医保用药对象，无须再继承整部目录。

保护对：
- 正例：`经办机构应及时结算定点机构发生的医保药品费用。` → Ec=1。
- 反例：`药品研发机构应及时支付办公室租赁费用。` → Ec=0。
- 反例：`医保费用字段不能为空。` → Ec=0。

### C. 03714：明确为药品扩展支付渠道漏Ec

原文：`推动多层次医疗保障体系建设,为创新药拓展更多支付空间。`

第一轮Ec=0、无候选排除。TOPICS Ec不含“支付空间/多元支付”，关系识别不含针对药品“拓展支付”的动作。依据手册，明确药品支付资源关系可以定性表达，不需已落实金额；但不能靠“创新药”单词推I或F。

建议：限于药品/治疗对象＋拓展/扩展/增加/完善＋支付渠道/支付来源/支付空间的当前关系。不要把“发展空间”“资料上传渠道”“优化支付信息系统”一起纳入。若只笼统谈多层次保障体系、不明确药品支付，保留原门槛。

保护对：
- 正例：`为相关药品扩展商业保险等多元支付渠道。` → Ec=1。
- 反例：`为创新药企业拓展办公空间。` → Ec=0。
- 反例：`优化支付平台登录界面和信息报送流程。` → Ec=0。

### D. 00206：无效治疗暴露与纯药代/方法描述须分开

原文：`健康受试者的研究一般可提供药代动力学和一定的安全性信息,有利于肿瘤患者在后续参与临床试验时,接受到更为接近于目标给药方案的治疗,减少肿瘤患者的无效暴露。`

第一轮E=0，无候选。该句后半段明确连接患者治疗、给药方案和无效暴露，不只是出现药代术语。TOPICS/实质效果分支未覆盖“无效暴露”。

建议：以“减少/避免”＋患者治疗/给药场景＋“无效治疗/无效药物暴露”组合纳入；不要泛化为任何“暴露”“剂量”“药代动力学”。

保护对：`减少患者接受无效药物治疗的暴露`可为E；`估计健康受试者的药代动力学暴露水平`不能单独推出E；`清除无效数据记录`为E=0。

## 3. 四个指定重点边界

### 01817：不是仅截止日期，当前确实规定病例资料覆盖范围

原文：`死亡病例和 SAE病例的报告小结应当是在安全性总结报告撰写的截止日期内,已完成的研究的相关病例,包括已完成研究并锁库但尚未完成 CSR 的相关病例,尚未完成研究但已锁库的病例也应酌情提供。`

同段前句明确要求递交临床试验报告及所有死亡/SAE病例小结；同来源source_paragraph限定“首次递交上市申请的抗肿瘤创新药产品”的安全性资料。

第一轮S=0，原因为**对象未建立**。`_form_only`实际上已对“死亡/SAE病例＋报告＋包括/应酌情提供”设置内容范围例外，故不能只继续放宽形式排除来解决。`RelationView.object_evidence`只检查当前、parent_paragraph/heading、有限关系，忽略该例同源明确药物适用范围；当前词“病例/临床研究”本身又不命中OBJECT。

建议：relations建立同源明确药物研究适用范围，仅用于对象消歧；dimensions保留当前“病例类别＋内容纳入范围”的安全证据动作。SAE缩写不能仅靠常识或文件标题推出药物对象。反例“安全性报告须于6月30日前上传”仍为纯手续；“药物研究的报告须包括所有严重不良事件病例”是内容要求。

### 02375：需要药品安全控制关系，不能把任何库存规则当S

原文：`遵循近效期先出的原则,避免出现过期药品。`

同一paragraph清楚写“加强医疗机构药品安全管理”，并界定采购、贮存、发放、调配、使用全过程的监测、质量检查和高警示药品管理。当前有“避免出现过期药品”的具体预防动作。S=0的机械原因是TOPICS S和专门风险分支均不覆盖过期药品/近效期先出。

可支持S=1，但理由应是当前过期药物预防措施在明确的药品安全管理范围内，不是“有效期天然等于安全”。应使用同段安全管理范围作为关系证据，不把它当所有兄弟句的标签。

保护对：
- 正例：安全管理范围下“近效期先出，避免过期药品进入调配使用” → S=1。
- 反例：“统计库存药品有效期月份用于财务盘点” → 不凭有效期给S。
- 反例：“为减少库存报损，优先销售近效期药品” → 不凭库存经济目的推S。
- 反例：“协议有效期届满后应重新签约” → S=0。

### 03423：有有限指代证据，但不能在泛句上硬补S/E

当前：`在开发可用于老年患者的药物时,需要将老年患者特征纳入考虑。`

同段紧随：`这些特征包括但不限于以下几个方面:`。已直接读取原PDF快照`00-baseline/source-files/462725c510f77f46-CDE-创新药适老化设计一般原则及考虑要点-2025.pdf`，印刷第2—3页完整六类特征确实包含：认知功能变化导致用药错误；运动功能变化增加药物误吸/误服风险；生理病理变化影响药代动力学、药效学和安全性。

因此人工不是毫无关系地借全文主题；“特征→这些特征→有限六类说明”存在可核同源连接，且当前有“纳入考虑”的内容要求。可是旧effective-semantic-unit只含这一段及来源快照路径，没有完整六类成员的结构化文本。第一轮关系未建立完整成员，dimensions返回0不是靠加一个安全/有效词表能正确解决的。

建议：只有relations能形成同段指代＋同版完整范围＋边界证据时，才消费为内容要求；不能让任何“考虑患者特征”都继承全篇S/E。若当前输入框架无法读取并记录完整六类范围，本轮保留分歧或明确材料依赖，不为得分写泛句特例。药代术语本身不赋E；本例E依据须落在所要求考虑的人群对药物药效反应变化上。

### 04526：同名综合审评内容与上市后果，证据充分且关系有限

当前：`第三十九条 综合审评结论通过的,批准药品上市,发给药品注册证书。`

紧前context `CTX-a64b4e84dad7eee23c66`：`药品审评中心根据药品注册申报资料、核查结果、检验结果等,对药品的安全性、有效性和质量可控性等进行综合审评……`

S/E均0；当前没重写安全/有效词，未产生同名审评标准内容关系。可安全修复为：同源紧前明确“对药品X/Y进行某审评”，当前同名“该审评结论通过/不通过”直接决定上市批准，形成标准—实质后果。它不同于只报告历史“已通过审评”或签发文书手续。

建议relations输出有限定义关系，dimensions消费已有S/E评价内容；不要在“综合审评”词上直接赋维度。保护反例：“综合审评材料已收到，录入文件编号”；或紧前审评只核材料格式，不能借另处安全有效要求。

## 5. 03780（Ec）的证据问题：不建议急于改为1

当前：`答:2025年…印发了《支持创新药高质量发展的若干措施》,明确提出增设商保创新药目录。`
