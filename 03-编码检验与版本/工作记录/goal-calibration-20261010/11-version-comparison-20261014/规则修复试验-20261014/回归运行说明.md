# 规则修复试验的回归与保护用例

只对77条原校准样本和200条已披露样本执行规则推断，不运行4481条全量。读取旧生产semantic_unit，直接调用RelationView与judge；行政ID、样本组别、人工答案和抽样权重均在判断函数外处理。合法待定与技术失败分列。

候选已参考200条开展调整，因此候选在这200条上的结果只能作为开发诊断。此前旧版的独立检验结果保持不变，不能把候选开发指标改写为新的独立验证。

## 运行

在项目根目录执行（输出目录必须是尚不存在的新目录）：

```bash
/Users/rainbow/.cache/codex-runtimes/codex-primary-runtime/dependencies/python/bin/python3 outputs/goal-calibration-20261010/11-version-comparison-20261014/规则修复试验-20261014/run_regression.py --output outputs/goal-calibration-20261010/11-version-comparison-20261014/规则修复试验-20261014/candidate-run-01
```

不指定`--output`时自动新建带时间的目录。用`--code-dir`可指定另一个五模块副本；默认当前试验目录下的`code`。`--baseline-only`只跑未改的原生产模块。每次候选测试都先复跑原生产模块并与旧保存输出逐项核对；基线不一致则不运行候选。代码执行期间变化也会拒绝保存候选结果，应在编辑完成后再跑。

## 输出

- `baseline-reproduction.json`：277条基线逐项一致性和原始泛化保护结果。
- `report.json`：77与200逐维四格、κ、精确率、召回率、F1、观察一致率、NULL、技术失败；200另外报告精确分数权重与加权指标；以及逐条标签变化、新增分歧、消除分歧。
- `candidate-predictions.json`：候选对277条的标签与理由，供排查使用；不覆盖生产输出。
- `metrics.csv`、`summary.md`：便于阅读的对照结果。

200条加权仅对应原1151条抽样框。NULL和技术失败均不作为负例。原始和加权四格使用同一批可判定记录，NULL权重与技术失败权重分别列出。

## 已完成基线检查

`baseline-regression`已完成，277条×5维的1385项判断全部复现旧规则输出。77的原始指标及200的原始、加权指标与历史核查精确相等。无技术失败。

自拟12项保护用例通过11项。唯一未通过的是“评价药品费用对低收入患者家庭的负担，保障其按治疗需要获得药品”，原规则识别经济性但漏公平性。普通企业/医院行政审批、文件名称/发布行为、数据可及性等近邻反例全部通过。保护用例用于发现明显过度泛化，不是语料人工标签，也不是独立验证集；不要为使测试通过而修改用例期望或针对句子写特例。
