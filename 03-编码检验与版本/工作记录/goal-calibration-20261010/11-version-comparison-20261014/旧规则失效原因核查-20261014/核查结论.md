# 旧规则为什么在77条全对，却在独立200条中漏掉创新性和公平性

核查日期：2026年10月14日。只读取已保存材料和代码，并对11条已保存输入做确定性路径复现；未修改规则、机器标签、人工答案或论文，未重新调用LLM，未运行全量编码。200条依用户纠正认定为独立真人检验。

**结论：确认存在规则实现的泛化不足；同时，后来独立样本的抽样框恰好不含旧规则的任何创新性/公平性正标签。未发现编号错位、生产版本误接，或按77个ID直接回填人工答案的证据。不能将本次样本的零召回直接说成旧版4481条全库零召回。**

## 1. 先排除版本和数据错配

- 77条校准和4481条生产的五个语义模块（source_packet、source_receipts、evidence、relations、dimensions）SHA-256完全相同。现存生产绑定的9个实现/配置文件均与当时冻结指纹一致。
- 77条在两个运行中的完整输入材料逐条相同，五维输出也全部相同。生产驱动改变了执行范围和绑定，不是偷偷换了一套分类逻辑。
- 200条的原始ID与真人结果集合完全一致，A、B盲号逐条对得上；旧规则实际交付的200条来源包与旧LLM对应来源包相同。既有核查另已确认这200条旧包与真人材料一致。没有发现按行号错配、样本错位或把不同原文拿来对照。
- 分类函数不接收行政记录ID；source_packet.py第124—139行剥离ID，RelationView第72—74行拒绝带ID/标签的输入。生产驱动第305行禁止读取reference.jsonl和04-calibration路径，保存的读取日志未出现这类读取；推理源码检索未见RECODE25特定ID表。11条确定性复现全部重现原保存标签。

这些证据支持“不是运行时按ID回填人工答案”。它们不意味着开发时没看过人工结果：冻结记录明确写有`calibration_labels_already_disclosed=true`，77条本来就用于调整规则。是否存在更广义的个案过拟合，要看匹配条件能否迁移，不能只看有无ID表。

## 2. 零召回还与后来抽样框的构成有关

|范围|条数|旧规则创新性正标签|旧规则公平性正标签|
|---|---:|---:|---:|
|校准77条|77|22|14|
|全量|4481|61|41|
|后来登记排除的开发材料及既定文本家族|3330|61|41|
|后来保留的独立抽样框|1151|0|0|
|从该框抽出的独立样本|200|0|0|

在1151条剩余框中，旧规则I、F各有1146个0、5个待定；在抽出的200条中各有198个0、2个待定。人工则识别出32个I正例和16个F正例。其中两条恰为旧规则待定，故二元可比记录上的漏判分别是30项、14项，召回率均为0，精确率因没有机器正例而无定义。

这是可复现的样本表现，不是计算错误。**但本批并非从旧4481全库简单随机抽样：它从后续登记的剩余1151框中抽取，且以较新规则/LLM的I/F标签辅助分层。**旧规则所有已识别I/F正例都处于排除框内，所以不能把该框的零召回直接外推到4481总体。这个范围限制不能反过来免除旧规则已经暴露的漏判问题。

## 3. 同一标准下的具体实现失效

以下每个失败例都有原始人工正例以及相应原文。右列77条成功例只是用于比较代码路径，不是拿旧人工答案替代新材料判断。

|维度|独立样本漏判|对应77条成功例|代码和路径证据|
|---|---|---|---|
|创新性|00133：允许已纳入优先程序的申请人提出“补充提交技术资料的沟通交流申请”|00138：对已纳入品种“与申请人进行沟通交流”|两者同一具名程序，但关系解析器要求“进行/开展/提供/安排……沟通交流”；00133的“提出……申请”不匹配，只有current单元，未接入创新对象及技术服务；00138成功生成named_mechanism。见relations.py第864—878行。|
|创新性|04197：专门审评团队内部解决技术问题，保证按时限完成审评|04162：组建专门审评团队|04197的对象检查直接失败，且资源解析只匹配“组建/建立/设立/安排……团队”，不能识别已组建团队执行工作；04162成功连接同段服务与研发范围。见relations.py第1596—1670行。|
|创新性|03477：注射器便于把持、设置大视窗、简化注射步骤以降低操作负担|03474：根据掰断便利性数据改善片剂、开发不同强度或剂型|变化正则包含片剂/剂型/包装/装置等词及改善/开发等组合，未匹配当前“注射器应易于……可配有……步骤应简化”；两个当前子句的change匹配均为空。见dimensions.py第99、701—715行。|
|公平性|00125：为优先程序药品优先配置审评资源|00138：为同程序已纳入品种进行技术沟通|00125当前有“优先配置”，但无当前缺口词，解析器未连接同版适用范围中的临床急需短缺分支；00138有特定沟通关系解析路径，能接入同一范围。失败不是缺少原文，而是缺少适用关系的泛化解析。|
|公平性|00141：不再满足优先审评审批条件时终止待遇|00038：不符合纳入条件时终止突破性程序|00141仅生成current单元；标准解析器的条件族识别要求“纳入/适用条件”或“资格审核”，未认出“优先审评审批条件”。00038成功生成cited_standard并带入完整条件。见relations.py第705—746行。|
|公平性|00132：临床急需境内未上市罕见病药可在上市审批后核查|00118：同类药品直接纳入优先程序|00118当前句同时包含缺口和机会，能直接命中；00132需要同段补对象、比较一般程序的审批前核查基准，旧规则只生成current单元，缺口及机会匹配均为空。原手册允许的关系没有被落实到代码路径。|

上述六个漏判及五个成功对照共11条，全部用保存的语义输入与当时绑定代码复现，结果与原始输出完全相同。完整单元、正则命中、关系类型及理由见`少量确定性路径复现.json`。

**因此，77条“全对”说明已调过的表达和关系路径能被程序识别，不等于它已经实现了手册允许的全部表达。**同一政策安排换成申请、执行、资格撤回或另一种器械改良措辞，多个必要关系就没有触发。代码虽然不是ID查表，仍可能对校准材料常见的句式和语境结构过度适配。

## 4. 对重做的直接含义

目前证据不支持“原样再跑一次就能好”，也不支持先让真人重做200条来解决。若研究仍要求保留规则与LLM两种方法的独立比较，应先修复规则对对象、同版安排、标准—待遇、实际支持和同义表达的处理，使用原77条作为回归检查，并用同义改写、邻近反例和不同文件中的同类关系检验泛化。不能只给这几个ID写补丁。

本次没有确认所有人工标签均无边界争议，也没有推翻五维理论定义。已确认的主要问题是**语义标准允许的关系，程序没有充分识别**；抽样框又使旧规则已识别的I/F正例全部不在本次检验范围中，两者必须同时说明。

如果随后用这200条诊断并修复新规则，原200条对旧规则的独立检验记录依然保留；新规则在同批上的改善是修复后检查，不能重新包装成从未参与调整的新独立检验。如何验证修复后版本，应在重做范围确定后再安排，本次不要求新增人工任务。
