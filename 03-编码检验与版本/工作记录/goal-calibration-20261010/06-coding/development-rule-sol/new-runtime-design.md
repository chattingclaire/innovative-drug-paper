# 共同五维规则运行器：最小实施设计（尚未执行）

设计日期：2026-10-10。身份：AI代码级开发审查；不是真人编码、可信裁定或独立效度检验。依据为共同手册v1.1开发版（SHA见source-bindings.json）及其变更日志。手册和共同材料仍在开发，本文只给实施接口；不建立新全量编码，不修改旧实现或论文。

## 实施选择

沿用已正确的原文偏移、Unicode匹配视图、来源哈希核对、结构引用闭合检查、当前锚点与语境锚点分存、同单元同维一次计数，以及可解释的药物风险/效果词汇和错对象排除规则。把有缺口的决定入口收拢到共同关系门槛，停用会绕过该门槛的旧正例分支。无需重做文本清洗、重新分句或重建全部词典；也不能把旧v25→v39多层增删链原样包一层新接口，就称为实现了v1.1。

本次只建立设计和差距清单。后续实施仍在本轮指定工作目录中建立可审查新副本，旧目录只读。先完成共同来源和手册的版本绑定，再做许可开发集合；完成共用参照、来源修复与冻结材料前，不启动全量。开发正确性依据原文关系和手册；不以旧标签、部门占比或开发分数选规则。

## 输入接口及适配

现有`packet-source-schema-sol.json`就是本次可定位的纯来源盲包schema，其`x-reader-contract`须同时执行。它的顶层和context采用`additionalProperties=false`，但45个structure字段仍容许任意object形状，`headers/row_cells`也有object分支；因此仅用JSON Schema验一次不能证明递归无答案。复用投影器的字段路径白名单，将`child_groups`和`row_cell_column_pairs`的子键逐项限制；对其他结构值只允许已登记的标量/数组。发现未知键即阻止包接入并记录具体路径，不能默默删字段，更不能扫描政策正文词语来删“labels/准确性”等合法原文。

许可pilot来源底稿共41条、280节点，252有text、28无text。本次只解析这些结构，不推断新标签。它不是盲包schema的直接实例：顶层为`id/text/pages/contexts/[source_page_attachments]`，部分context含`source_document`，来源字段为`sha256/locator`；schema则要求`blind_id/unit_text/...`和`source_sha256/source_locator/provenance_status`。用一个中性adapter完成下面转换，不能把同名字段直接认作已满足契约。

1. 只从许可集合选记录。`id`只用于输入选择、回接和审计，不传入维度判定函数；不使用ID到标签映射。`text`映为`unit_text`；pages进入当前单元source_ref或管理映射。不得重新切分当前单元。
2. 保留每个原CTX ID、所有28无text容器及递归引用。不得仅保留有text节点，也不得按已判断的维度筛语境。
3. 将原`sha256/locator`转换为schema要求的字段。`source_document`保存在管理映射或经明示修订的schema中；不能临时放进一个任意metadata对象绕过限制。
4. `provenance_status`按实际认证等级转换。原件SHA可关联不等于逐字定位已完成；13处待核与后续补材状态以共同修复清单为准。候选稿相符不能冒称原件认证。所需材料待核影响哪些维度，由当前依赖决定。
5. 绑定同版来源及官方解释。结构化source registry保存source SHA、文档/制度身份、发布日期或生效期、实际位置和认证等级；这些是可核来源事实。药类/注册类别释义保留共同原文，不能预存“所以I=1”。
6. 盲ID与人/规则/LLM可见顺序可不同；`unit_text+source_title+contexts+attachments`的规范化JSON内容SHA必须相同。改语境或附件就另材料版本，首判保留。

## 关系解析的最小范围

每个候选先保存当前完整命题及其原文偏移，再决定能用哪一种语境。

|路径|允许补足的内容|必须保留的限制|
|---|---|---|
|对象/指代|标题或明确父句解释药物、研究、患者治疗对象；唯一确指前文|不能由对象身份生成维度；有竞争对象时按当前作用对象消歧|
|共同父谓词|当前清单成员与直接父谓词组成自身命题|不读兄弟项给该成员赋维度；共同修饰、例外、或/且仍有效|
|实质总领—完整成员|当前本身有评价、证据内容、实质条件—后果关系，用被指向完整范围补足|纯结构引导不汇总；不能仅凭冒号或“以下”判断；保留记录不新增计数|
|操作性标准援引|当前要求满足/核验标准，或以标准决定授予、维持、限制、终止待遇|精确到条/款/项与完整并列范围；五维都可检查；不推定所有条件失败|
|具名机制行动|当前设立/实施/开放/适用/限制/撤回同一安排，补同版对象和直接机制|身份、沿革、印发或一般宗旨不足；历史实施按行动时期；不复制安全义务、费用和其他平行措施|
|同政策对应解释|共同包已核解释说明当前措施的对象、问题、机制|解释—措施逐一映射；一个措施的缺口不扩散到兄弟项；不递归“有关规定”|

`relation_result`由运行器从当前和共同原文即时计算，包含当前行动锚点、使用路径、实际CTX引用、完整范围、适用时期、共同父谓词与否定/条件/例外作用域。它不是输入端事先审定的语义证书。只有必要依赖确实缺失时请求补材；没有确指缺口且完整命题未达到某维门槛时记0。

否定统一保留，不统一排除。输出要分清药品属性否定、证据不足、支持设立/限制/撤回、资格条件失败或整个推断被否定。标签表达议题在场，理由不能写成药品已安全/有效/创新或政策已公平。并列“或”逐支留痕，有一支符合可记1，纯手续支不继承另一支；“同时”完整读完共同范围。

## 五维决定接口

```python
judge_dimension(current, source_graph, resolved_relations, manual) -> DimensionDecision
```

参数只包括当前原文、原始来源图、即时解析关系及手册。不得读管理ID、部门、样本层、旧标签、机器答案、置信分数或开发预期。手册hash、代码hash用于复现，不能成为记录白名单决定结果。

S沿用药物损害/风险及其证据的候选，逐项核药物关系；单纯质量可控、数据安全、疾病负担不成立。E沿用明确疗效/健康收益/效果证据的候选；删除仅“治疗价值、目标适应症立题依据、临床需要”即E的快捷分支，作用反应的评价与仅药代/机制术语分开。原有原文偏移和错对象排除可直接迁移；候选的词汇命中不是最终判据。

Ec统一处理制定、改变、比较、评价、实质内容提供/核验和条件—支付后果。确认已存在的支付标准/范围不需新金额，也不需“准确性”措辞；只核字段非空、签章、模块递交仍0。成员通过直接父谓词形成支付变更适用/限制关系时可成立；普通目录申请身份不能补成支付。

I路径分别留痕：I1当前技术新颖/创新价值，知识产权须连接技术新颖性、实质改良或创新资格，权利存在或状态本身不足；I2实质改良或明确局限/操作障碍—具体变化—改善关系；I3创新/实质改良研发对象—可用具体支持安排—直接联系三项俱全；I4具体创新/改良资格或按对应药类时期核明的资格—当前权利义务后果。一般指南的风险/试验规范不默认I3；重大适应症变化、给药形式变化、裸1类身份不能自动I。法定创新分类的待遇使用不改称研发支持。

F只有两个入口：明确药品/患者治疗公平评价或实质信息要求；以及患者获取/持续治疗/可负担对象与可辨认获取差异、按需保障缺口或支付能力的直接联系。普通供药、目录成员、电子处方渠道、一般临床管理和患者自付责任不单独成立。上游须目标治疗缺口与以此为条件的优先/申请/资源机会相连；无有效选项、境内无获批选项、实际供应不足分别记录。

## 0/1/null、理由与原文输出

每维返回独立决定，保持五个一级维度；I/F路径是理由字段，不能新增计数维度。

```json
{
  "blind_id": "A-000001",
  "packet_version": "共同材料版本",
  "manual_sha256": "64位SHA",
  "content_sha256": "64位SHA",
  "runtime_sha256": "64位SHA",
  "coder_role": "AI_rule_runtime",
  "decisions": {
    "S": {
      "value": null,
      "basis_path": null,
      "current_anchor": null,
      "current_proposition": null,
      "context_evidence": [],
      "reason": "明确待补的来源及其对本维判断的影响",
      "needed_material": [{"reference": "确指地址", "missing": "缺失原文或关键关系"}],
      "rule_conflict": null
    },
    "E": "同一DimensionDecision结构",
    "Ec": "同一DimensionDecision结构",
    "I": "同一DimensionDecision结构",
    "F": "同一DimensionDecision结构"
  }
}
```

这是结构示意，不能作为完成的判读行；E/Ec/I/F在实际schema中须为对象。`current_anchor`及`current_proposition`均为`{start,end,text}`，满足当前原文切片逐字相同。前者定位内容，后者保留完整否定、条件、比较和例外。语境依据为`{context_id,start,end,text,source_sha256,source_locator,usage}`，在实际CTX原文中逐字可查；表格或图形另记录对应单元格/附件位置。输入不改字，规范化只用于定位。

- 1：至少一个符合判据的当前实质关系；保存路径、完整命题、实际语境及关系理由。I3另填研发对象、支持安排、直接联系；具体F另填患者药品对象、公平关系及当前安排/评价；概括F不补造具体障碍。
- 0：材料充分，经本维门槛检查未成立。保存最接近候选及未满足的必要条件；没有候选时简述当前实质内容与本维无直接关系。不能只写“未命中正则”。
- null：本维依赖的关键原文、关键指代/解析确实缺失，或真实手册冲突尚待共同裁定。明确缺什么/哪条冲突；其他充分可判维继续判。当前已有独立充分正例时，不因另一个无关依赖待核清空已可成立的本维。

不能把运行器未实现某种语法伪装成材料缺失，也不能给未知填0。开发期间遇到已发现但尚不支持的语法，登记implementation_error/coverage task并使该开发运行不满足交付检查；在正常标签文件中不输出虚假的规则null。运行manifest保留尝试记录数、错误记录和未完成状态；未经解决不进入总体统计。手册许可的null与程序错误分别计。

建议最低构造对照集（都不是真实检验答案，本次未运行）：

1. ID/文件名/排序/部署目录变化、原文及结构关系相同，标签与理由关系不变；来源hash变化应拒绝旧映射。
2. 无text容器/完整成员/例外缺失应被发现；缺失仅影响依赖它的维度。一个完整S命题与另一缺失I机制并存，保留S判断。
3. 纯“条件如下”不汇总；“符合下列条件可获得具体机会”的实质总领按完整范围判断；清单成员不继承兄弟项。混合引导与实质内容不一律清空。
4. 否定、不确定药物效果仍可E；依据保留“未/不”。“不符合同版确指标准则终止待遇”记录标准议题而不声称全部条件失败；报告个药既有状态不自动展开。
5. 一般创新药风险管理义务可S，不能仅由指南对象加I3；实际开放创新研发研究反馈机会可I3。电话/递交形式不自动增加I。
6. 历史明确实施支持安排可用行动时期同版机制；2025方案不补2024行动；仅历史名称不展开，确指关键机制缺失按维null。
7. 裸“1类创新药”对象与“该类资格决定续约待遇”分开；化学药/生物制品/中药按对应版本核类别；中药3类不得跟随1类称技术创新。
8. 普通重大适应症或剂型变化不自动I2；明确使用障碍与拟用改变—改善关系可I2，否定或尚未证实不清除议题。
9. 确认已有支付标准/范围的实质内容可Ec；字段非空、签章或模块操作0。当前成员＋父谓词“方可申请调整支付范围”可Ec，不自动F/I/E。
10. 一般渠道流转/目录成员/供药监测不足F；同版解释确指患者所需药品保障缺口与该措施的联系时再按具体关系判断。解释不扩散到兄弟措施。
11. 患者能否负担药物命题可F；基金可负担、单独价格/自付责任不足F。概括公平评价可F，但不虚构具体获取障碍。
