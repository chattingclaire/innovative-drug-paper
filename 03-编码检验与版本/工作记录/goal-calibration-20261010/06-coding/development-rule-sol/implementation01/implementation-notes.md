# implementation01 开发实施说明

仅处理 `development-reference41-v11` 固定来源夹具的41条记录、205项五维判断。五维规则由确定性Python执行；没有LLM调用、旧运行器导入、旧预测输入、ID到结果映射或部门分支。管理ID在 `semantic_unit` 时移除，预测完成后由runner回接。来源SHA、位置、时期和标题只供来源/同版关系核验。

`source_packet.py` 是原始来源格式的明确adapter，并未宣称输入直接符合盲包schema。它保留无text节点，递归限制键和值形状，拒绝答案/选择字段、未知键、重复JSON键、悬空CTX、失配SHA及越界附件路径。实际核验41条、286个CTX和15张附页；未由source_ref的SHA推断药类/时期。

`relations.py` 只从当前原文及共同语境即时生成对象、父谓词、完整清单、操作性标准、具名机制、同政策解释、同列单元格的有限关系。它不预存维度许可。具名机制仅补对象与研发便利；同政策解释要求同来源和政策文号/日期/标题，并映射当前措施的问题。规范化仅用于匹配；decision保留完整当前原文，以及实际引用的语境原字面范围。

`dimensions.py` 分别执行S/E/Ec/I/F，I保留I1/I2/I3/I4理由路径，F区分概括信息与具体患者机会关系。同维至多一次。0提供实质门槛理由，null限定为当前实际依赖的材料缺口；未实现语法抛出实施错误，不伪装材料null。

`runner.py` 明确接收来源、手册、manifest、授权SHA及条数；新目录专用且拒绝覆盖。它先写freeze，执行全部记录，验证精确引文，保存执行访问日志和错误，再封存预测SHA。文件访问守卫禁止reference，禁止未授权输入及输出目录外写入。技术错误记录保留，并使执行封存状态为失败，不能进入正常开发指标。

`evaluate_development.py` 是独立事后进程。先检查预测封存和SHA，之后才打开共同AI开发参照；保留全部41条、205项比较及null分母，给出逐维TP/FP/FN/TN、precision、recall、specificity、F1、balanced accuracy和kappa。此处kappa仅表示与AI开发共识的一致，不是真人编码员信度或正式独立效度。

首次构造测试日志 `behavior-run01.txt` 保留21通过、8失败（29项）。未调整预声明期待；修正围绕本药指代、实质内容与形式分支、父支付后果和同列价格值的一般实现。关系独立构造审查也保留首次失败及修正：局部行动绑定、局部行动时期、同源父句、边界截断、同政策解释、资料归档与机制实施分离。它们均发生在首次41条实际判读之前，未读取开发参照。

附页处理：15页核了文件SHA；额外只读查看两份流程图，对照已有共同文字转写。没有把读图结果私加到规则输入。若其他必要图形关系未进入共同文字，须作为公共输入接口问题交主任务统一补材，本实现不声称已自动OCR或认证所有页的实质内容。

本目录是开发原型，不证明已覆盖所有政策语法。首次实际输出和错误永久保留；后续若按原文关系修正，必须另立implementation版本与运行目录，不回写首次记录，也不根据分数挑选结果。未访问1444保留池、coverage01的36条正文，未运行全量。
