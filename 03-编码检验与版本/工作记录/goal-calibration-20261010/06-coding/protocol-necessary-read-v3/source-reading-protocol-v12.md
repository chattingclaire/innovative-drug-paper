统一来源读取协议 v12

三种方法使用 `source_only_interface_v12.py rule|model|human RECORD_ID` 的默认完整共同bundle。端点名称不改变来源字节。`unit`仅正文，`--record-only`仅逐行投影，均不构成完整共同材料。版本/hash与实际来源、物理页和原图绝对路径随包提供；只开放路径、加载文件字节或返回bundle，不自动证明当前执行者读过或使用过它。

1. 先读当前正文及其原文/转写/图表序列化身份，再读管辖标题、父段、限定、例外和有关子项。根据CTX父子、编号组与边界读取适用范围；EOF与容器节点只是结构边界，不当作政策正文。
2. 表格读取实际表头、行组、相关单元格及合并/跨页关系。图读取节点、支路、图例、图注和实际印字的运算词。图未印字时保留未知运算；排列/括线不能自动补OR或AND。同版工作方案有独立明确原文时，作为另一来源关系读取，不能冒充图上印字。
3. 有确指标题、条文、文号、年份或简称时，读取共同来源库/索引对应的同版原件和完整有关条件、共同谓词、例外。同SHA确认同一快照；跨SHA同版须有源内标题/时期/版次及明确关系依据，文件名年份、PDF创建时间或相似内容不能单独定版。并非整文件资源可用就意味着所有段落自动适用于每个单位。
4. 104段新视觉转写保留自己的source role；填写指示、右/下例示、占位词、例示副标题、源标题和页码分开。17框只表示展示分区与同框关系，坐标为人工宽松有界框而非逐字OCR。“示例封面”是区域名称；原件实际文字另存SOURCEVISUAL。例示药品事实和占位符不自动升格为政策命题。上述角色读取不提供任何五维结论。
5. 必要材料缺失、版次未决、角色/边界不清、截断或所需视图尚未读入时，记录 `source_requests` 并停止依赖该材料的结论；未知不能代替否定。自足部分的来源读取可继续。00064七月程序原DOC出处已核，但所援技术指南版次未唯一确定；保留未决，不再搜索或倒填十一月正式稿、候选征求稿和一般法规范。

执行方式：

```sh
python3 source_reading_protocol_v12.py prepare RECODE25-04200 --run RUN_ID --reader model > run-source-log.json
python3 source_reading_protocol_v12.py check run-source-log.json
```

`prepare` 生成当前正文/CTX及已知同框角色读取要求、共享资源清单、空读入/使用收据和 `scope_review=pending`。此时check必须不能通过。操作者按实际源关系完善必要范围、确指状态与请求，并在真实阅读后填写收据；准备动作不产生阅读证明。

读入收据逐资源记录源SHA、视图与视图SHA、实际读取定位、完整/部分/截断/失败状态、当前读者与真实事件。阅读视觉转写文字是text，不是image。文字规则只记录实际消费的text/geometry，不能因JSON有图片路径就报告看过像素。资源生产阶段AI已看原页与300dpi页的记录只属于来源转写溯源，不能继承为当前方法或真人的阅读事件。

使用收据与读入分开：已读可以未用，可用可以未读。`used`必须指向同资源、完整且recorded的实际读入收据；还须记录使用范围，例如源身份消歧、确指原文、版式关系或引文。check只检查源读取记录要求、版本与依赖停止状态，不能独立证实人的实际阅读，更不是语义正确性、真人独立编码、模型性能或联合freeze认证。运行日志由ROOT在真实执行时另行封存。
