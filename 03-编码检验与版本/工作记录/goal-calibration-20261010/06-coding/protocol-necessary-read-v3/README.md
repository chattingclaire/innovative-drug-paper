# Native necessary-source reading v3

This implementation binds the sealed v13 source addendum over the unchanged v12 complete-source interface and the exact v1.3 execution manual. The original ten roots remain mandatory; the eleventh `source_bundle_extension` is present only in the 59 affected bundles. Full-material SHA includes the added original paragraphs. Original current text, source_record and CTX are preserved.

The field profile comes from all 4,481 sealed frame records and all 1,298 owner field paths. Public resource fingerprints and literal role/status values were collected in one mechanical bytes/shape/identity pass. No record was selected for coding in that pass. `frame-render-costs.json` records exact compact/indented complete-packet byte costs; `all-frame-technical-prebatch-plan.json` is a cost plan in original frame order, not an experiment sample or execution.

`parent-binding.json` freezes the owner seal/accessor/inventory, whole-material record bindings, all-frame field shape/profile, manual and operational budget. `load_owner` validates those bindings. `make_packet` checks the complete bundle against its sealed whole-material SHA, then preserves the original bundle without projection. The new inventory retains original resource IDs, source SHA, structured JSON pointer, raw HTML location with original CR/LF and literal text-view SHA. Public text quotation uses its original JSON pointer in a side file; it does not invent CTX.

The v2 finite necessary-read gate is retained. Availability does not establish necessity, actual reading or use. Further necessary views are declared from original source relationships; unrelated available views can remain unread. Missing or unresolved necessary material stops dependent dimensions with null and concrete material requests. `required_read_complete` remains false until all declared necessary views/references have complete recorded reads. A used view requires the same resource, source SHA, view, view SHA and complete recorded read. The gate checks record consistency and dependency handling; it does not certify semantic necessity, correctness or independently prove reading.

The budget is an operator guard for these artifacts. It counts the worst complete R/W/H rendering, all instructions/manual/schemas, an output reserve, original CTX and SHA-deduplicated asset bytes/pixels. The unit ceiling is 41. Native provider capacities, actual model, token usage and wire parameters remain unavailable/null. Output reserve is a planning allowance, not a permissible truncation point: preserve the first complete output and record any overrun without truncating or rejudging it to fit a budget.

Execution metadata stays outside initial coding prompts. R1/R2/R3 use identical prompt bytes; W changes JSON indentation and equivalent complete-file locators/hashes; H changes only the first heading from 判读要求 to 判读说明. Each condition/batch/technical attempt uses a new chat; batch history is shared within that chat. At most three technical attempts are allowed, with identical frozen input and no prior answer, feedback or continuation. The first complete technically valid output is selected immediately, including valid null/material-request handling. No semantic retry, cross-attempt assembly or comparison occurs before every condition and batch is sealed. Requested allocation is gpt-6.1-sol with ultra; an assigned setting does not establish actual provider telemetry.

Only the new v13 binding, locator and rendering integration checks were run. Original 167 and v2 19 checks were not rerun. Preparation created no coding chat or candidate label output. Old v1/v2/B4 seals remain intact. `parent-binding.pending.json` and the preparation failure record are retained as history. The later authorized development77 input export belongs in a separate new directory and does not modify this implementation or the sealed source package.
