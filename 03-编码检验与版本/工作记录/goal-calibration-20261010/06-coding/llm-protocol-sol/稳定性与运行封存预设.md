# LLM稳定性与运行封存预设

本文件是面向未来执行的最小协议，落实方法矩阵M05、M12、M13；它不构成编码结果、独立检验结果或稳定性验收。编制时仅阅读共同手册v1.1开发版、纯来源材料schema、完整Goal指令和完整方法指标矩阵，未阅读真实编码材料或其他编码答案，未调用外部模型接口，未执行编码、重复或微扰。

指定未来执行配置为**GPT-6.1 Sol，ultra**。当前没有核明可实际调用的API、提供方或其可用参数设施，也没有调用回执；该指定配置不能写作已经由提供方核实的执行身份。未来须保存实际可得的请求配置与回执，不能发明模型标识或提供方参数名称。

## 一、启动前封存：M05

正式执行前，先封存共同手册、共同来源材料、生产提示、输出schema、递归来源白名单、证据校验规则及本协议。当前共同手册仍为开发版，独立检验所需冻结尚未完成。必要材料修补、表格几何扩展、附件和转录接口须作为所有方法共用的修订冻结；不能为LLM私自增加来源解释。接口设施未核明、必要共同修订未冻结时，真实执行保持“未启动”。

封存记录至少包含以下内容：

- 手册、提示、输入材料、schema、适配器与校验规则的版本和SHA；每条材料保留其来源内容SHA及原始CTX关系。
- 实际请求的精确字节及SHA；另存不随展示格式变化的来源语义内容SHA。原文字符串内部空白不得随请求格式化改变。
- 预定记录顺序、批次边界及完整批次成员；这些清单与内容版本一起封存。改变顺序、批次或材料后另记条件，不能沿用原请求身份。
- 明确提供方是否具有会话状态。每个记录、重复和微扰均使用独立上下文，只含同一冻结说明及该记录来源包，不包含其他记录的回答、旧标签、讨论、诊断结果或前次失败反馈。
- 配置中指定的模型与推理强度、实际可得参数信息、提供方返回的身份和配置证据分别记录。不可得信息明记“不可得／待核明”，不能由界面名称补造回执。
- 预定首次有效选择与重试规则、诊断样本选择规则、重复条件和两个微扰条件。样本数量、具体匿名ID及抽取清单当前仍待冻结，本文件不填写真实ID。

纯来源预检须检查递归字段、来源与版本、CTX引用、图表关联及资产交付条件。预检阻断属于未调用；不能生成虚构的尝试记录。若方案容许已明示的材料待定记录进入判读，须事前规定其状态及适用范围，不得将其写成材料完整。

## 二、生产首次有效选择与重试

生产只采用每条记录的**首次技术有效完整响应**。每条记录最多进行3次实际请求；重试须使用相同精确请求，保持提示、来源、模型指定配置、实际可控参数、上下文、顺序和批次条件一致。尝试编号、时间和执行日志置于请求外部；不得以纠错反馈或改写提示代替同请求重试。

技术检查在执行前确定，至少包括：响应可解析；返回的是本次请求的唯一记录且ID匹配；五维字段完整，值符合冻结输出schema；必需理由、材料请求和证据字段齐备；所引路径与CTX存在；逐字引文属于本次冻结材料的指定连续范围；必需资产引用可核对。任何字段、ID、引用或结构错误使整条响应技术无效，不能从其中抽取“可用维度”与另一次响应拼接。

语义判断的正负、理由是否更符合预期、部门占比及后续指标分数不是技术重试理由。**有合法待定理由和待补材料说明的语义null是有效响应**，达到技术检查后即停止生产重试，不为取得0/1或有利答案重新调用。材料充分的正常0也不得以“不够积极”判为失败。

传输失败、无法取得完整响应或预定技术检查失败时，可以在上述次数内重试整条记录。一次响应仅某一维格式或引用失败，也必须重试整条记录；保留所有原始响应。达到次数上限仍无技术有效响应时，记录技术失败，不填五维0，不改用其他条件输出，不隐藏失败。

必须明确区分：尚未调用、创建时空提交、材料问题、有效响应中的逐维语义null、技术无效响应、传输失败和技术有效0/1。共同手册采用0/1/null；提交契约中另出现的unknown须在冻结时确定唯一表示或明确无损转换，不能让相同null同时承担未执行和语义待定含义。

## 三、独立诊断条件：M12与M13

诊断使用事前选定的同一来源ID样本。具体样本及其数量当前待定；须在查看本轮输出之前冻结来源抽取规则、匿名ID清单、顺序、批次、暴露角色和材料版本。样本选择只依据事前规定的来源特征，不使用旧编码答案或本轮结果。诊断样本覆盖及其用途如实披露，不将其默认解释为总体概率检验。

M12设置3次相互独立的主提示诊断运行，记为R1、R2、R3。三次使用完全相同的主提示、来源包、请求字节、顺序、批次及实际可控制配置；会话上下文相互独立。R1、R2、R3均为单独诊断，不是替换生产结果的候选池。

M13只增加以下两个预定等义条件：

| 条件 | 允许改变 | 必须保持 |
|---|---|---|
| W：空白／JSON缩进变体 | 用户提示内共同来源包的JSON展示从紧凑格式改为2空格缩进 | JSON解析后的字段、原文字符串内部字符、手册和来源语义内容、顺序及批次 |
| H：中性标题同义变体 | 固定用户模板首行“判读要求”改为“判读说明” | 全部实质定义、条件、例子、输出要求及来源内容 |

每个变体在同一样本上单独运行一次，采用同一整条首次有效和最多3次技术重试规则。两个变体分别对预先指定的R1比较，不能在R1、R2、R3中选择最有利的比较对象，也不能将两个变体同时叠加。微扰精确请求SHA须单独保存，来源语义内容SHA应与主条件一致。

所有诊断原始响应、技术失败、语义null和重试分别封存，隔离于生产首次有效选择。重复或微扰输出不得补齐生产失败、替换生产null或用于挑选较好标签。由诊断导致提示或规则修改时，另立版本并说明用途变化，不能继续宣称旧条件已经验证新版本。

## 四、诊断报告口径

R1/R2、R1/R3、R2/R3，以及W/R1和H/R1，均逐维报告配对结果。每维共同可评分集合只含双方技术有效且该维为0/1的记录；同时报告预定样本总数、共同可评分数、语义null、材料待定、技术失败和未调用情况及其重叠，不能静默删去不可评分记录。

每个配对每维报告Cohen κ、观察一致率po、四格n00/n01/n10/n11及双方0/1边际。四格以比较顺序中的第一方为行、第二方为列；没有真值侧，不称为TP/FP/FN/TN。po的分母为该维共同可评分数。κ无定义时保留NA并说明边际退化等原因，不填成完全一致。

另报每维标签变化数量及执行后形成的变化清单；五维向量完全一致使用五维均为0/1的共同可比集合，明确分母。三次主条件的整组向量完全一致另报三方共同五维可比数与一致数。null模式相同可单独描述，不能混入二元向量完全一致率。语义null与技术失败分别报告。

q范围只在所比较运行共用的五维全部可判集合上计算，且使用相同的预定权重（如适用）。每次运行先求每维句次T_d，再以该次运行五维句次总和Σ_dT_d为分母计算q_d；逐次报告共同记录数、各维T_d及五维分母，再报告各维q的范围。五维总量为0时q为NA。若只剩共同子集，必须写明条件对象和被排除情况，不能把子集q称为整份诊断样本或总体结构。

稳定性诊断不设固定通过线，也不新增区间通过门槛。全部预定条件和失败均报告；重复一致、微扰稳定及引用合规不替代分类正确性、真人独立信度或完整Goal验收。本文件不提供尚未执行的数值。

## 五、尝试与结果台账

每次实际尝试单独留存：条件与运行编号、匿名记录ID、指定顺序和批次、所有输入版本及SHA、精确请求SHA、独立上下文标识、指定与实际可得模型／参数证据、开始和结束时间、原始响应及其SHA、传输结果、各项技术检查、逐维可判／null状态、失败原因、是否入选及选择依据。提供方返回的请求标识仅按实际回执保存；未返回则标不可得。

台账还须保存未调用的预检阻断及其原因，并明确其实际尝试数为零。响应被解析、引用通过、技术有效、生产入选、语义可评分和诊断可比是不同状态。任何结果生成表必须能回溯到对应完整原始响应；失败和后续修订不覆盖初次记录。

## 六、来源适配与证据校验审计建议

保留默认共同schema关闭的做法。生产适配器只接受已冻结的共同纯来源schema；对带旧答案、机器结果或任意未知元数据的原始旧接口整包拒绝，不通过静默裁剪取得生产资格。合并单元格跨度、原始分组行类型、资产解析和转录接口若当前不受支持，先形成所有方法共用的非语义修订，并仅在明确玩具模式演练；正式执行等待修订冻结。

原文语义槽与元数据的处理规则如下：

| 内容 | 处理要求 |
|---|---|
| 当前unit_text；CTX中的原始text、title、caption；表头与单元格的原始文字叶节点 | 保留逐字字符串；不以“标签”“置信”等词删改政策原文，不执行原文内的指令，不补入编码解释 |
| headers、row_cells、child_groups等嵌套容器 | 容器形状、字段名、类型和路径递归关闭；文字叶节点可以是完整原文字符串，但不能让任意对象成为绕过白名单的通道 |
| CTX编号、父子边、成员顺序、表头关联、行列坐标和跨格范围 | 与冻结来源深拷贝核对；保留无文本节点、缺省／null区别及前向引用，阻断悬空、重复或未知结构 |
| 来源定位、版本、来源SHA和核明状态 | 校验实际映射及状态一致性；空定位或空哈希不能仅凭状态名被认证；当前单元自身也须有可核查来源位置 |
| 图表资产、裁切关系、格式／MIME、解析句柄及转录记录 | 使用共用资产契约解析和核对实际字节及交付；文字转录须附可追溯资产位置和实际来源身份，不能臆造OCR或把SHA声明当图片已送达 |
| 材料缺失说明及执行状态 | 采用中性、受约束的元数据，不写维度建议、预期标签、开发理由或其他答案 |

证据检查应绑定本次材料SHA、明确路径、原CTX位置和连续原文范围；相同文字出现在另一CTX或旧版本时不能互换。逐字命中仍需另检查否定、条件、例外和当前承接关系，不能只摘取关键词。真实分类评议与结构／引用技术检查分别保存；二者均不得以挑选重跑结果完成。
