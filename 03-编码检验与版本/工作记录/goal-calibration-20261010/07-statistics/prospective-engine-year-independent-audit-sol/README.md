# 年度接口独立 AI 技术审计

原年度扩展存在一个已复现的源年份成员不完整问题，详见 `audit.json` 的 YEAR-001。修复候选保存在本目录的 `metrics_engine_repaired.py`，并已实际运行构造控制；原年度引擎与原控制交付均保持不变。这是 AI 技术审计，不是人类专家评分、正式研究验收或真实年度统计。

审计只读取指定年度目录的新代码、契约和构造控制交付，以及旧分域引擎源码、旧契约和年度分析计划 `report.json`。没有读取真实标签、Gold、实际800或4481条款数据，也没有生成真实年度发现。原作者的 `control-report.json` 仅用于了解其声明，seal 的核对仅证明文件完整性；独立结论来自本目录重新构造的输入、手算与实际执行。没有在原目录运行 `run_controls.py`。

## 已确认问题与反例

原 `analysis_scopes` 在父范围条款全查时，把已赋年数量直接当年度总体 N，并将空已赋年掩码解释为无来源。原 `_year_attention_fields` 只检查标签 null/失败，未检查源年份成员是否完成。

最小反例为两条全查条款：第一条已知2020年，只有 S=1；第二条年份为 null，只有 E=1。请求2020、2021。原输出认定2021年无来源且 N=0，2020年 N=1、S 的最终 q=p=1。若 null 条款属于2021，2021便有来源；若它属于2020，完整年度2020的 S q=p=1/2。标签已完成、ID已全查均不能消除源年份不确定性。

实际原输出见 `cases/census-unknown-year-original-output.json`，对应的候选修复输出见 `cases/census-unknown-year-repaired-output.json`。修复候选在每个年度父范围统计未赋年条款数及原权重质量，受影响年度的总体 N 保持 null；非空年度的完整 q/p 返回 null 与 `unresolved_source_year_membership`。空年度返回 `NA(no_assigned_year_observation_unresolved_parent_source_year)`。已赋年子集的 known-hit 量、标签不确定界限和相应复抽诊断仍保留，并标明没有包含源年份成员不确定性。null 年份条款保留在 unknown 桶，未分摊到年份、未填0。

独立冻结的 `no_source_views` 可以另行证实某个年度域 N=0，仍按原规则传播到子域。其依据是另行来源证据，不能从空样本或未完成年份映射推出。未知只影响含有这些条款的父范围：alpha 未赋年不阻断完全赋年的 beta。源码中的 `full_census` 继续仅表示原设计无抽样误差；新增说明明确其不消除源年份不确定性。

## 独立构造控制

`run_independent_audit.py` 在本目录生成构造输入、实际源年份投影文件及哈希，并调用原引擎、旧分域引擎和本目录修复候选。主体跨层控制只有6条款：原层权重3、5、1，两个非全查原层均被年份切开。2020年手算 HT 分母为10，五维 T=[4,8,5,0,1]，B=18；q=[2/9,4/9,5/18,0,1/18]，p=[2/5,4/5,1/2,0,1/10]。q合计1，p合计9/5；reference 的 B=9，rule 的 B=18，验证各方法独立归一。

主体概率控制实际使用5000次复抽、seed20261010。由于两个非全查原层 n=2、m=n−1=1，全部可能的权重只有四种，按原层 FPC=2/3、4/5手算枚举。观察到的5000×6矩阵每行均属于这四种，原层权重和分别恒为6、10、2；年度权重和在四个取值间变化。所有年度/部门/分域交叉掩码保持6列，实际只生成一次完整 W；区间与原设计协方差均按手算核对，修复前后 W 完全相同。

其他控制覆盖真0、五维全0、无来源、概率样本无年度观测、源年份 null、标签语义 null、缺返回、整方法失败、单维失败、绑定篡改、启用后遗漏年份、非法年份值以及未冻结项目拒绝。14个独立旧接口组合比较整个返回值，覆盖三阶段、概率/非概率、命名分域/旧式范围和三种 guard 模式；旧、原年度和候选修复输出一致。年度仍不是抽样新层，年度局部有限计数 guard 不可用。ALL点门槛与既有项目复核保持，未新增逐年、CI下限或半宽门槛。

年度接口实现的是验证标签账本的年度域聚合。来源/组件/系列敏感性、相邻年度差、真实全量 q/p、趋势与因果结论未在此实现或计算。公布的接口含 year、department×year、domain×department×year；独立 domain×year 未注册，不把它算成实现违约。

## 交付与重现

- `audit.json`：45项独立检查、一个确认问题、边界和结论。
- `metrics_engine_repaired.py`、`input-contract-repaired.json`：仅本目录保存的修复候选及明确变更后的契约。
- `cases/`：自行构造的源年份工件、输入、每次执行的确切输入及实际输出。
- `legacy-independent-regression.json`：14个整个返回值回归比较。
- `input-seal.json`、`output-seal.json`：只读依据、构造输入、输出、源码和说明的SHA256；seal自排除避免递归哈希。

在本目录依次运行 `PYTHONDONTWRITEBYTECODE=1 python3 run_independent_audit.py`、`python3 seal_audit.py`、`python3 verify_seals.py` 可重现控制并封存核对，写入也仅发生在本目录。重现会更新本目录审计时间与输入/输出文件。原件不会被覆写。

源年份工件的真实日期证据仍由调用方验收；哈希与 sealed 声明不认证人类身份或来源事实。修复候选没有被提升到原年度交付，不能把本目录通过构造检查写成原年度引擎已经修复或真实研究已验收。
