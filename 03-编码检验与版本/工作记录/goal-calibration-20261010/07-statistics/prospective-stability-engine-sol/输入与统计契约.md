# 离线输入与统计契约 v1

契约版本：`prospective-stability-engine-sol-v1`。`input-contract.json` 提供 registry 或 ledger 的 JSON Schema 形状；`stability_engine.py` 负责更严格的跨文件、字节、次序、首次选择和数学检查。Schema 未单独证明这些语义约束。输入 JSON 重复键、NaN/Infinity、未知闭合字段和缺失必要字段会被拒绝。

## 一、先封存 registry

`data_mode` 显式为 `synthetic_control` 或未来的 `prospective_registered_inputs`。当前交付全部是前者。`registration.status=frozen_before_response_read`、带时区的冻结时间、登记 ID 和 `verification=declaration_not_independently_verified` 必须填写。冻结声明及其哈希不证明真实执行前已经冻结。

五维顺序固定 `S,E,Ec,I,F`。`sample.assigned_records` 每条含唯一 assignedID、正且有限的权重、材料状态、待定理由、来源原字节引用、来源解析后语义 SHA、CTX 对应表及其 SHA、材料版本。权重可用十进制或精确有理数字符串；计算内部使用 Fraction，0/1 标签不允许用 bool 或 1.0 冒充整数。

`ordered_assignedIDs` 必须与 assigned_records 的次序完全相同；完整批次成员平铺后也必须精确等于这一次序。每条只出现一次，不能换批/换序后沿用原条件。概率样本需要逐 ID 正 π≤1、权重严格等于 1/π、框 SHA 和全部目标单元正 π 声明；非概率输入不能填虚构 π 或把分析权重称设计权重。全核模式逐 ID π=权重=1。样本域、抽取规则和范围限制必须明确。

`common_artifacts` 固定六项：manual、prompt、output_schema、adapter、technical_validator、protocol；各项保存版本及实际文件 SHA。共同配置精确记录 intended_model、intended_reasoning_effort、provider_requested、全部可控制 request_settings、提供方会话状态是否核明、实际身份未被请求名称/哈希证明的状态。request_settings 是调用设施实际提供的字段，工具不猜提供方参数名称。

prompt 文件是明确的请求组装契约，含 system_prefix/system_suffix、user_prefix/user_suffix 与 payload_template。系统内容由前缀+同一手册原字符+后缀组成；用户内容由前缀+同一来源 JSON+后缀组成。payload_template 必须各含一次且占据完整值的 `{{SYSTEM_CONTENT}}`、`{{USER_CONTENT}}`、`{{REQUEST_SETTINGS}}` 槽。所有请求按 UTF-8、紧凑、键排序 JSON 外层序列化生成并与登记请求字节逐字核对。原文字符串内部空白不变。

`conditions` 按 P、R1、R2、R3、W、H 各登记一次。P 为生产首次结果角色；R1/R2/R3 为三个诊断主条件；W 为 compact→indent2 来源 JSON 展示变体；H 为用户首行“判读要求”→“判读说明”。各条件绑定同一配置、共用版本、样本/权重/顺序/批次计划；每个 assignedID 另存精确请求文件及 SHA、来源语义 SHA 和 CTX SHA。主条件字节完全一致；W/H 只允许该单项变更。多出的 R4、未登记条件、两个变体叠加和未冻结版本均拒绝。

`context_unit` 必填 record 或 batch；各运行每个登记单元保存不同的 planned_context_id。每次尝试另保存该 ID、单位、无前次输出暴露声明和未独立核验状态。独立声明既允许 true 也允许 false，但 verification 必为未核验。record 只表示逐记录上下文计划形状符合预设，并不证明实际独立；batch 明示与逐记录独立上下文预设不同。分批不是 repeat，重试不是 repeat。没有 native77 默认资格。

retry_policy 固定最多 3 次实际请求、整条首次技术有效完整响应、同字节重试、合法语义 null 停止。comparison_plan 固定 R1/R2、R1/R3、R2/R3、W/R1、H/R1，三方为 R1/R2/R3，两个变体基线始终是 R1。stability_pass_threshold 与 confidence_interval_gate 必须为 null。

registry_content_sha256 是删去该字段后 registry 的 UTF-8、键排序、紧凑 JSON SHA；ledger 另绑定 registry 文件完整原字节 SHA，展示换行也不能绕过原字节封存。

## 二、完整 ledger、原响应和检查报告

ledger 的六个 run 都必须逐条保存全部预定 assignedID，次序和 order_index、batch_id 与注册完全一致。不能靠缺行隐去未调用或失败。每条含 attempts、not_called 和 first。

每次实际 attempts 从 1 连续编号，最多 3；保存开始/结束时间、执行所请求配置、请求/材料绑定、上下文声明、原样的提供方回执、传输结果与原因、原始响应文件引用及外部检查报告引用。时间不能早于声明冻结或倒置重试。JSON 配置按规范字节比较，区分 1、1.0、true；不能依赖 Python 的 1==true 相等行为。回执不可得时 request_id、returned_model、configuration_evidence 均为 null。已见 returned_model 字符串互相不同则拒绝同条件；字符串相同仍不认证实际模型。

传输失败不虚构解析/引用检查；如取得部分原始字节也保留引用。传输成功的原响应固定为完整单记录 JSON：assignedID、labels、reasons、null_reasons、material_requests、evidence。labels 必须五维齐全，每维只能整数 0/1 或 null。逐维理由及 evidence 槽齐全；null_reasons 和 material_requests 必须恰好对应 null 维度，且有非空理由与待补说明。格式/ID/引用等技术失效使整条失效，不从失败响应拾取部分维度。

validator_report 固定绑定检查器实际 SHA、本次请求 SHA 和本次原响应 SHA，含八项布尔检查：parseable、id_match、five_dimensions、response_schema、source_binding、context_evidence、contiguous_quote、assets_reference，以及失败原因。前四项由本引擎实际复核，与报告不一致则拒绝。后四项来自冻结检查器的结果，本引擎只核对绑定，不能把它们写成自己已重新完成的来源/引用检查。真实分类是否正确不是技术重试依据。

first 输入只能为 null，或本条件本 assignedID 的最早全部技术检查通过响应的 run_id、assignedID、attempt_number、raw_response、parsed_response_sha256。引擎重新从 attempts 求 earliest valid，并逐字核对输入 first；不能提交后来更好的响应、其他条件响应或按维拼接结果。一旦技术有效，即使含语义 null，也禁止后续 attempts。最多三次失败保留 technical_failure；只有三次耗尽才标 failure_exhausted_three_attempts=true。部分失败快照保留剩余名额和不完整状态。零 actual attempt 必须有 not_called/precheck_blocked/material_blocked/creation_empty 状态与原因。

输出 firsts.json 不丢原绑定：保留本条件/ID/尝试号、原响应/检查报告/精确请求路径及 SHA、来源/CTX SHA、解析响应 SHA、标签、上下文声明、提供方回执。audit-ledger.json 保留全部尝试、技术/传输失效、零调用状态及首次选择。P 的 firsts 独立列出，不能用 R1/R2/R3/W/H 补齐 P 的失败或 null；P 的输出只覆盖本 registry 的 assignedID，不能冒称完整生产全域。

## 三、统计与分母

每个固定配对逐维二元可比集合 C_d 只含双方技术有效且本维均为 0/1 的记录。第一条件为行、第二条件为列，四格为 n00、n01、n10、n11；不存在真值侧，不使用 TP/FP/FN/TN 术语。

N=n00+n01+n10+n11。第一方 0/1 边际为 n00+n01、n10+n11，第二方边际为 n00+n10、n01+n11。

Po=(n00+n11)/N；Pe=((n00+n01)(n00+n10)+(n10+n11)(n01+n11))/N²；κ=(Po−Pe)/(1−Pe)。N=0 时 Po/Pe/κ 为 NA；Pe=1 时 κ 为 NA，说明边际退化，不写 1。另报 n01+n10 标签变化数量、逐 ID 双侧标签及 raw 绑定、双方阳性数与 second−first 阳性变化。加权版用同一预定权重替代格数另算；属于输入指定权重的 Cohen κ，不是有序等级 weighted-kappa。

所有配对和三方共同域都列 scheduled_n、scheduled_weight_sum、joint_comparable_n、共同权重和、共同 ID、排除 ID、边际状态及状态联合模式。语义 null、技术失败、未调用分别计数；材料待定是重叠属性另报总体数和可比集中数，不把其加到排除数里造成重复计数。若准许待定材料进入有效判读，必须事前 allow_pending_material_for_valid_response=true。

五维向量可比集合 C_5 要求所比较每次运行五维全为 0/1。双次向量率为五维向量相同记录数/|C_5|；三次整组率为 R1=R2=R3 的五维向量记录数/三方 C_5。同步给原始及加权分母和逐 ID。三次逐维一致另有自己的 C_d，不混用五维分母。null 掩码相同只在技术有效且至少一侧/一方有 null 的记录另描述，明确 is_binary_stability=false。

每个配对及三次主条件的 q 仅用本组 C_5 和相同预定权重。各运行先算 T_rd=Σ(i∈C_5)w_i y_ird，再以该运行自己的 Σ_dT_rd 作分母：q_rd=T_rd/Σ_dT_rd。原始 T/q 使用 w_i=1 另列。共用记录、权重和、排除状况、每次五维 T、Σ5T、各维 q 和范围均输出。Σ5T=0 则全部 q 为 NA；只要某运行 NA，该组 q 范围不删除 NA 运行后冒称完整范围，而保留该维 NA 和缺失运行清单。不能将 C_5 子集 q 描述为整份诊断样本或总体结构。

本工具不设稳定阈值，不算 CI，不以区间下限添验收线，不计算分类正确性或真人独立信度。非概率/概率/全核和输入是否完整分别披露；总体框覆盖与独立性未核验，因此输出不作任何总体声明。版本、参数、来源、次序或批次变动不能沿用当前 repeat 名称；需另立版本和用途，不能选择最有利条件、多数表决或诊断结果替换首次生产结果。

## 四、封存与复现

相同 registry/ledger、被绑定资产和引擎字节生成同一 report.json、report.md、firsts.json、audit-ledger.json。seal.json 枚举输入/输出 SHA 和大小及引擎 SHA；任何输入 SHA 不符、缺行、字段漂移或首次绑定不符在统计前拒绝。SHA 是字节完整性工具，不认证实际提供方身份、独立上下文、抽样过程或分类正确性。原输出目录非空时拒绝覆盖。
