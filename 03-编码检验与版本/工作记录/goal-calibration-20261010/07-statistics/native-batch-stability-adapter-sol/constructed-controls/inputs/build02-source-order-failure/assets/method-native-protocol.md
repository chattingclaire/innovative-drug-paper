# Codex原生对话批次协议 v1（事前变体，待执行）

本变体适配目前可用的Codex原生新对话：创建工具显式请求`model="gpt-6.1-sol"`、`thinking="ultra"`。一次新上下文按固定顺序处理41条开发单元，**批内共享上下文**，后条可能看到前条推理、工具读取或回答；不能称为41个独立会话。它不是原API协议runner.execute的实现，不具备逐条独立HTTP transport、真实wire body或provider回执。

原API协议、程序及封存清单保持原样。本目录仅为设施适配准备：未读取新执行对话、预测、旧开发答案或admin映射；未编码真实单元；未执行R1/R2/R3/W/H。本轮已知“另一个新对话正在执行41条首轮”来自任务说明，未在此查验。**本协议只对封存后启动的运行事前生效，不追认已启动首轮采用了本schema或重试规则。** 编写者已有开发暴露，不能因此更名为未暴露编码员。

## 1. 身份及可得证据

| 层次 | 可保存内容与表述 |
|---|---|
| 指定配置 | GPT-6.1 Sol／ultra；来自任务指令 |
| 原生工具分配 | 完整create_thread请求及实际工具接受/创建返回、threadId、hostId、时间；仅称Codex工具分配证据 |
| 实际执行遥测 | 实际provider模型/推理配置、temperature、seed、token上限、wire body和provider请求ID均不可得，逐字段null |

不能由界面名称、模型自报或请求中的model/thinking补造实际模型遥测。原API协议的transport-receipt不适用。不得把原生创建次数、批次尝试数换算为底层API调用数；API调用数设null。本准备阶段真实原生编码运行数为0。未来工具证据尚未取得的字段留null，不能先写成工具已接受。

## 2. 一次初始提示、同版完整材料

每个attempt新建原生对话，使用create_thread，不fork旧对话、不复用执行对话、不自动沿用旧结果。完整初始prompt一次提交；它包含原主系统文本的内容、原用户模板的完整判读要求、逐字完整共同手册、完整输出schema、固定41条清单及共同来源包/资产读取顺序。原生任务prompt是用户任务内容，**不能声称原系统提示已被设置为该产品的system role**。实际应用系统指令及不可见后台状态记不可得。

实质定义、必要语境、否定/条件/例外、单位计数、0/1/null、I3对象—支持—关系和具体F对象—公平关系均沿用完整共同手册v1.1开发版，不增加私有政策名单或阈值。源文本中的操作指令当原文；部门、标题、其他记录及旧标签不成为判据。其他方法须使用相同版本、全部来源语境、图表及共同转录。原手册、source schema和原输出的每维技术字段不因原生设施而摘要或改写。

冻结初始prompt精确UTF-8字节及SHA；手册原字节/SHA；source_manifest逐条内容SHA及完整包SHA；有序ID JSON的SHA；批次边界；资产原字节/SHA；schema及本变体版本。模型能读到的材料包只有纯来源，管理层/权重/旧答案不进入可见文件。原共同来源schema的递归关闭、当前来源定位、合并表格与转录缺口仍由共同材料工作处理；原生可打开文件不能证明这些缺口已解决。

固定阅读顺序为：完整手册与技术schema→整批有序目录→按目录逐条完整当前/全部CTX/所需共同图资产→每条逐维判断→单一整批提交。初始prompt提供全批材料或明确完整来源文件/读取契约，不采用不断追加单元的用户多轮推送。不得主动打开前轮结果、诊断回答、参照或机器文件。已读取文件的SHA只证明文件身份，不等于全文进入可见上下文。

## 3. 容量、阅读及历史日志

事前批次单元上限为41；实际上下文token上限、输入/输出token限额及可用余量目前null。41是本变体固定批次数，不是模型容量保证。每批事前登记字节数、单元/CTX/图资产数；如设施提供真实限额才记录其证据，不能自行填temperature、seed或max_tokens“默认值”。

记录每次读取的原路径/资产ID、来源SHA、范围、工具名/事件ID、可见返回长度、是否摘要/截断/失败及图像是否实际打开。完整手册逐字可见、全部当前/CTX范围与有序目录核对；无文字结构节点、原附表、表头、合并跨度和图箭头保留。图资产文件存在、已打开、自报使用和理解正确分别记录。关键图不可辨认按共同手册逐维null及具体补材请求；打开失败或材料未交付属于阅读技术失败，不生成null占位答案。共同转录若必要，另版本向所有方法同步，不私自补维度解释。

日志区分：未开始、创建失败、读取失败、可见输入截断、已知上下文压缩、输出中断、格式/引用失败、完整性不可核明、首次格式有效封存。已知截断/压缩不能靠摘要手册、删CTX、原对话催续或纠错继续后仍称同条件首判。保留实际文件/消息和失败范围；需要缩小/拆分批次时，先另立材料/批次协议版本，并对以后所有比较条件使用一致划分，不能追溯改写本次41批次身份。

一个批次的前条历史可能影响后条，必须披露。未来多批设计每批另起对话；若实际复用同一对话，登记跨批可见消息、结果、工具范围及复用原因，视为条件偏离，不能与预设“新上下文批次”混为一组。记录任务初始消息、外部后续消息、读取工具事件和已知压缩；看不见的内部状态记unknown。不同threadId只证明逻辑对话标识不同。read_thread摘要不能当原始模型响应或完整历史凭证。

## 4. 整批首个格式有效选择与封存

提交是一个native-output.schema.json对象，含条件/运行/批次身份及输入SHA，items按冻结顺序完整列出41条；每条沿用原输出schema。全部五维0/1/null、完整当前连续原文、必要CTX引文/位置、理由及I3/具体F字段均须齐备。技术检查含JSON解析、重复key、schema、SHA/ID/顺序、条数、连续引文、引用来源与实际可读资产记录；不评判标签好坏。

选择单位为**整个批次响应**。一个记录的格式或引用失败使整批技术无效；不能抽取其中记录或维度，不能跨attempt拼接。合法逐维null有具体缺口/规则冲突请求时属于有效提交，第一份完整有效批次立即入选；null比例、评分、部门占比或语义偏好不得触发重做。

每条件最多3次技术attempt，按启动顺序编号。只对创建/阅读/截断/输出/格式技术失败重试；每次用新对话、同初始prompt字节、同手册/材料/资产/顺序/批次，显式相同model/thinking分配。不得在原对话发纠错、续写或解释前次失败；后次不看前次回答及失败内容。原生内部读取工具顺序/返回若实际有差异如实记，不冒称已取得相同wire请求或精确控制全部参数。

每个实际出现的提交候选先按原始UTF-8文件字节或实际可取得消息文本封存、SHA和时间，再做技术检查；文件不得覆盖。取不到完整原生消息时，提交文件SHA是文件证据，不是provider原始响应SHA。读不到完整候选记完整性不可核明，不补造原文。保存全部attempt、失败、工具分配证据、选择编号及理由；未启动不创建语义答案。任何语义修订/补材重判另版本保留，不能覆盖初判。

## 5. 独立批次重复及等义微扰预设

R1/R2/R3各用一个全新对话，处理同41条、同版共同材料、同序和同批次划分，使用相同初始prompt字节及原生分配参数；独立性单位是运行批次。每个条件内部技术重试仍按整批最多3次新对话规则。它们不替代开发首轮或生产首判，不投票、不补生产失败/null。

W单独新对话，仅将共同来源JSON展示由紧凑改为2空格缩进；解析对象、原文字符串内部字符、顺序、手册及schema相同。H单独新对话，仅将用户内容中已固定的中性首行“判读要求”改为“判读说明”；其余字节相同。W/H不叠加，都固定与R1比较。若来源只能通过文件读取，W须封存同源展示文件及提示的对应引用变化，先明确差异清单；不能一边摘要文件一边称格式变体。

事前封存共同来源样本/41条匿名顺序及诊断用途；本目录不读取真实ID或生成该清单。R1/R2/R3/W/H各自选择及所有候选失败记录全部封存之前，不读取另一条件答案、不计算变化/κ/q、不查参照、不向后续条件反馈答案。**所有5条件选择或明确失败且封存后**才解锁比较。不得根据结果更换R1、最佳prompt、批次顺序或合法null；修改实质判据另属构念敏感性版本。

比较沿用M12/M13：每维共同二元可评分数、κ/po、四格/双方边际、变化数、null/失败/未启动；五维向量完全一致及三次变化；q仅在各条件共同五维可判集合计算，以五维句次总和为分母，分母0为NA。没有新通过线，不把批内共享历史结果解释为逐条独立模型重复。它只描述指定手册/材料/顺序/批次/原生设施下的稳定性，不替代真人独立信度、机器效度、共同冻结、Goal验收或论文。

## 6. 实际操作清单与本交付

1. 协调者先冻结上述prompt、来源/有序清单、资产、schema和批次契约，填ledger计划字段，不读本轮回答选设计。
2. 每attempt以明确model/thinking新建原生对话；保存实际工具请求/返回，记录不可得遥测和已知历史。执行者只读共同材料，按固定顺序返回单一完整批次文件。
3. 协调者先封存候选及阅读/历史日志，再技术核验，记录首个有效整批编号；失败完整保存，必要的技术重试另起新对话。
4. 5条件均封存后才能开启比较。此准备阶段不创建编码对话、不读取真实标签、不计算实际稳定性。

native-execution-ledger.blank.json是空白计划/观察台账，null不代表已执行。native-output.schema.json保持原每条证据字段并增加批次封装。validate_native.py和toy-format-check.py只对构造数据核验条数/顺序/来源绑定/引用/null、整批首次有效、新对话与历史/截断拒绝、封存比较门及不可得遥测；不运行原runner.execute、不调用create_thread或provider、不生成真实标签。这些程序不能认证原生创建回执、完整可见历史、来源真实性或图资产字节交付；共同来源纯化/递归白名单、资产核对和实际阅读事件仍由协调者按已冻结共同契约核明。toy核验结果与本目录文件SHA另封存；原协议清单不重写。
