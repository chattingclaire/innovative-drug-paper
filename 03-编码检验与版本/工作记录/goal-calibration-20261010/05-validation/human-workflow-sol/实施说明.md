# 真人执行流程与工具草案

本交付只完成 AI 制作的通用工具与构造 toy 检查。实际作者为 GPT-6.1 Sol / ultra；没有读取剩余 1444 条正文/语境、抽取真实检验 ID、生成研究标签或执行真人验证。真人名单、真实首判和真实裁定均为 pending。所有新文件仅在本目录。

## 执行次序

管理员先落实真实 A/B 的相关专业背景、培训及开发接触记录、独立声明和真实匿名代号。真实姓名与签名放在独立管理的身份登记册，包内只出现匿名代号及登记册 SHA。裁定人另登记；无法落实独立第三人时，将真实 A/B 讨论与负责人裁决如实记录。

在任何独立检验答案出现前，冻结共同手册、完整中性来源包、已完成抽样/全核名单及统计方案。当前 v1.1 明示开发用途，不能直接在清单里改成 frozen；需另有实际版本冻结记录。本工具不选择 n，不执行抽样，也不读取任何辅助预测。600 与 1444 仅为公开规划方案，实际选择尚未锁定；接口接收未来确定的任意合规分配，不根据答案追加或择分。

来源管理员先认证当前记录位置与必要语境。无 text 结构、原 CTX 指向、完整成员/共同谓词、表头/合并单元格/跨页关系均须保留；不要按是否有正文过滤。来源无法核明时保留明确的待补状态，不能删掉难题或声称 ready。出处实际二进制、导出的原页图及必要裁剪分别绑定 SHA。原页不能只留下路径而没有资产。

生成器一次读取四类输入：未来冻结 source 包、冻结 draw manifest、冻结 manual、两位实际执行者匿名代号。它输出管理员专用映射和 A/B 两个可分开交付的文件夹。两方来源内容一一相同，编号和呈现顺序不同。机器/规则/LLM后续应使用同一冻结中性内容；不同接口的原始文件 SHA 不作为语义相同的证明。

两位真人按 [真人操作说明](真人操作说明.md) 独立完成，各自先核验、再封存。材料请求仅向管理员报告中性问题；统一补材后创建新 round，`parent_round_id` 指向前轮。首判原字节永远保留，变化另记，不把补材后答案回填成首次答案。双方初判封存后先评价真实人—人信度，再另存机器盲裁定。工具不生成讨论答案、裁定参照或统计分数。

## 文件与接口

- `workflow.py`：Python 3.10+ 标准库 CLI，提供 `build`、`verify`、`seal`。无联网调用、模型推断、抽样或指标计算。
- `schemas/*.schema.json`：来源 manifest、来源逐行记录、draw manifest、可见包、包 manifest、标签行及提交元数据的 JSON Schema。`interface_schemas.py` 可导出同版 schema。运行时还核对跨记录关系、哈希、引文和值类型。
- `toy_checks.py`、`toy-verification.json`、`toy-example/`：完全构造的 4 条来源及 2 张小原页图替身。A/B 各 4 条 × 5 维，40 个交付标签均为未填 null；不含语义答案。测试中的内存符号值只检查字段约束，不作为任何例句的判断。
- `identity-registry.template.json`、`execution-ledger.blank.json`：真实身份和阶段记录模板，当前全部 pending。
- `delivery-manifest.json`：本次允许输入 SHA、作者身份、实际运行边界及交付文件 SHA；清单自身 SHA 在最终交付消息列出。

source 目录含 `source-manifest.json`、一个 JSONL 和原始二进制/图片资产。每行固定私有 `record_id`，其余为当前原文、`unit_source_ref`、标题、完整 contexts、attachments 和中性材料状态。manifest 绑定原始文件/原图实际字节 SHA。来源字段均作严格白名单及深层检查，任何未知结构键硬失败并要求在冻结前明确修订接口，不静默丢弃。

draw manifest 仅记录已经确定的 ID、版本/SHA、呈现 seed、真实人匿名分配及管理员设计字段。层、N_h、n_h、pi、权重和家族编号进入 `admin-private/mapping.json`，不进入编码员包。当前实现限定输入为单阶段分层 SRSWOR 或全核，核对 pi=n_h/N_h、weight=1/pi 以及实际层数量；若未来选择其他设计，须先明确修订接口，不能冒用此公式。至少 2 条的限制只为“两个不同顺序”接口在逻辑上可满足，不是研究样本量门槛。

本接口相对原 `packet-source-schema-sol.json` 是显式草案扩展：增加当前记录的 `unit_source_ref`；允许已声明的 `table_group_row`/`preceding_flattened_table_data_row`；增列 `physical_merged_cells`、`physical_grid_row_index_zero_based`、`source_group_context_id` 和 geometry。nested 键也白名单。该草案没有自动冻结为共同材料接口，也不迁移真实材料。未来冻结应将此接口变更一并登记。

共同内容 SHA 使用 UTF-8 JSON（ensure_ascii=False、sort_keys=True、紧凑分隔符）对 `unit_text + unit_source_ref + source_title + contexts + attachments` 的对象编码。它排除盲号、顺序和执行者，但绑定当前来源位置及所有语境/图引用。该五字段公式与旧草案四字段公式不同，版本必须如实说明。材料状态/问题说明仍原样复制给双方，并由 packet 字节 SHA 绑定。双方同包哈希多重集、原图资产哈希均校验；上下文 CTX 保持一致，不改写为断链编号。

A/B 顺序由各自事前 seed 确定：SHA256(seed) 转整数后按已排序 ID 进行固定 shuffle。若两个完整顺序偶合，B 固定循环移动一位，并记管理员日志；不寻找有利 seed。编号为 A-/B- 六位序号。呈现 seed 与真实抽样 seed、统计 bootstrap seed是不同用途。

source 的 labels/predictions/expected/gold/score/confidence/旧编码理由/抽样层/权重等字段禁止传入；深层对象也检查，不只是顶层删键。原文中正常出现“标签”“score”等词保留。白名单及哈希不能识别藏在自由文本中的人工泄露解释；来源管理员仍须审核材料仅含原文、必要来源结构与中性缺材说明，不能附标准答案、结果导向证书或机器理由。manual 也须经真实内容冻结审核，不仅声明状态。

## 提交格式与核验边界

空白标签使用 `completion_status=unfilled`；全部 value 为 null、证据和理由未填。完成标签行改为 complete 后必须恰有 S/E/Ec/I/F；值只能为整数 0/1/null（拒收 bool、浮点和字符串）。五维均保留当前连续引文、证据路径和理由。使用语境的连续引文须在本单元对应 CTX 的 text/title/caption/headers/row_cells 原文中出现；不自动空格归一、拼接或从其他记录借证据。当前位置由 `unit_source_ref` 和 CTX 的 source_ref 定位。图片证据的附件 SHA、位置和实际查看清单均绑定，转录/几何的真实性由真实源证据审核负责，脚本不声称视觉认证。

1 的路径为 S_content/S_information、E_content/E_information、Ec_content/Ec_information、I1/I2/I3/I4、F_general/F_specific；多路径用 `+`，例如 I1+I3。0 用 not_met，null 用 unknown。路径只是手册依据的存储方式，不增加维度或改变判据。I3 三项及具体 F 三项须各附当前/CTX/图片来源证据与解释。每个 null 有具体请求类型、当前确指锚点、待补材料和决定性理由；正常未满足不以“可能还有背景”为由无限请求。

提交 metadata 绑定 executor、身份登记 SHA、packet/manual/labels SHA、记录数/五维数、实际开始及提交时间、独立声明、AI 草稿参与和开发接触、图片阅读声明。脚本将 AI_draft、真人事后复核、pending 身份拒收为独立真人首判；真实身份与独立执行仍由管理员核实，不能由一串声明自动证明。标签形状合规、连续引文准确、分类正确和实际真人执行是不同事项。

`seal` 保存核验后的原始 labels/submission 字节，记录接收时间及 SHA，目标目录和锁文件以排他创建方式避免本工具覆盖。核验后文件若改变则拒收。封存文件设只读，但同一账户/管理员仍可能改权限；如需强不可改存证，应另用真实访问控制和只写一次备份。当前交付没有部署此类存储。原首判、补材重判、协商裁定分别封存，不用重判文件替代初判。

## 权限与交付

目录按 0700、普通文件按 0600（封存文件 0400）建立；源资产路径禁止绝对路径、`..` 和符号链接。A/B 只应分别收到自己的 `coder-A` 或 `coder-B` 文件夹，管理员 `admin-private`、draw manifest、完整 source 包、另一方材料与身份登记册另控权。

文件模式不能隔离同一 OS 用户下的兄弟目录。真实部署必须使用分别管理的用户账户或逐人云目录权限，并实际测试 A 看不到 B/admin、B 看不到 A/admin；不要把包含两方及管理员的总目录一起发给真人。当前仅创建本地草案，真实分发权限仍 pending。

## 运行命令

本次只实际运行下面的 toy 检查（所有测试写入本目录的临时文件夹）：

```sh
python3 toy_checks.py
```

以下是未来接口示例，当前没有运行，也没有真实 source/draw/执行人可代入：

```sh
python3 workflow.py build --source-package FUTURE_FROZEN_SOURCE --draw-manifest FUTURE_FROZEN_DRAW.json --manual FUTURE_FROZEN_MANUAL.md --executor-a HUMAN_CODE_A --executor-b HUMAN_CODE_B --output NEW_ROUND_DIR
python3 workflow.py verify --packet-dir OWN_PACKET_DIR --labels labels.jsonl --submission submission.json
python3 workflow.py seal --packet-dir OWN_PACKET_DIR --labels labels.jsonl --submission submission.json --destination NEW_FIRST_SUBMISSION_SEAL
```

`build`/`seal` 不能覆盖既有轮次。格式拒收只表示需补齐/更正真实执行记录，不把缺材改 0。补材建立新的被冻结包与新 round，保留前轮来源和首判；现有工具不会合并或抹去旧答案。

## 统计契约和待落实项目

实际统计应绑定允许输入中的 v2 修正版。机器四格顺序 TP/FP/FN/TN，Specificity=TN/(FP+TN)、NPV=TN/(FN+TN)，不能采用旧说明反置的分母。主 CI 为同设计、共同重复权重的 Rao-Wu FPC rescaled bootstrap，5000 次、seed 20261010、逐指标 95%；线性化用于诊断复核，稀疏/零格另有有限总体 guard，NA 不填 1。当前工具仅保存未来统计方案 SHA，不实现或替代统计 engine。

用户项目点值目标保持：真实 A/B 协商前逐维 Cohen κ≥.80；两最终机器各逐维 κ/Precision/Recall/F1≥.80。没有增加 CI 下界、半宽、Specificity/NPV 或 toy 分数验收门槛。可判四格按每维双方 0/1 子域分析，null 的九格/加权未知率及全域边界另报；不得整行删除难维、丢掉非响应权重或把剩余池推断外推为全 4481。
