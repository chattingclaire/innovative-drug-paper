# 真人独立编码操作说明（待实际执行）

本说明是 AI 制作的执行草案。当前没有真人名单、真人独立首判或真人裁定；共同手册 v1.1 仍为开发版。正式执行以事前冻结的共同手册、来源材料包及版本清单为准。本说明不替代完整手册。

1. 管理员向两位真实编码员分别交付各自材料包。只打开自己的 `packet.jsonl`、共同手册、`packet-manifest.json`、原图资产及空白表。不要查看机器/规则结果、旧标签、另一编码员答案、管理员映射、抽样层或权重。政策原文可能透露部门，不把该过程称为部门身份双盲。培训和参与开发的范围如实登记。
2. 每条先读完整当前命题，再读其必要语境。语境只补全当前已表达的对象、指代、条件、比较或确指安排；不从标题、全文宗旨或兄弟项继承维度。保留无 text 结构节点，按其 CTX 引用读完共同谓词、成员、边界和表头。凡有原页/原附表附件均实际打开，核对合并单元格、分组行和跨页，不仅看文字导出。
3. 每条分别填写安全性 S、有效性 E、经济性 Ec、创新性 I、公平性 F 五维。`1` 表示当前命题及合法必要语境达到手册的实质门槛，不表示药品已有优势或措施已经有效；否定、条件、过去/未来时态均不单独决定排除。材料充分而没有相应关系为 `0`。关键确指原文、版本、结构/指代缺失或真实规则冲突为 `null`，具体写待补什么及为何影响该维；不要把未知填 0，也不要连带清空其他可判维。
4. 每维保存当前连续原文锚点、实际用到的语境 CTX 编号和连续引文、图证据位置及关系理由。保留否定、条件、比较和例外，不拼接词片作原文。0 写最接近的候选内容为何不足；null 写具体材料请求。使用 I3 时列创新/实质改良研发对象、可用支持安排及直接关系三项原文证据；具体 F 列患者药品对象、可指认公平关系及当前安排/评价。概括公平评价使用 F_general，不补造具体障碍。原图的转录/几何证据须记录实际查看并由后续源证据审核核实。
5. 空白表的 `completion_status=unfilled` 和五维 null 是未填占位。完成一条后改为 `complete`；完成提交中仍为 null 的维度必须有真实具体缺材说明。标签只能是整数 0、整数 1 或 JSON null。不要删除全 0、纯结构引导或暂缺材料的记录。
6. 仅用本轮包内原文与共同手册判读，不自行外查或请 AI/他人生成标签，不与另一编码员讨论，不参考预期分布或一致率。材料问题可向管理员提出中性请求，管理员向双方同步同版补材。首判保留原版本；补材/规则变化后的重判另建轮次，不覆盖首判。
7. 全部已分配记录五维填完后，保存自己的 `labels.jsonl` 和 `submission.json`。真实填报开始/提交时间、匿名代号绑定的身份登记 SHA、独立声明、AI 标签草稿是否使用、开发接触范围、逐张图片查看时间和材料请求数。格式核验通过后由管理员封存原字节、SHA 和时间。未完成或身份 pending 的表不能记为真人完成。
8. 双方首判均封存后才进行分歧讨论和另存裁定。人—人信度使用协商前原始首判。裁定者保持对机器答案盲态，并核查相同手册及源证据；一致项也按事前方案审核。无真实独立第三人时，如实称 A/B 讨论加负责人裁决，不称独立专家金标准。

AI 标签草稿、真人事后复核和真人协商前独立判读必须分别留档。真人核对或修改 AI 草稿属于事后复核，不能倒记为真人独立首判。软件格式通过也不证明真人身份、独立性或分类正确。

依据：共同手册 v1.1 第一、二、六、七、十及“使用身份与本版本状态”；验证设计的 `human_independent_execution`；未知与分母政策。正式冻结版本若有修订，管理员须明确版本变更，不能把新材料写成原包已有。
