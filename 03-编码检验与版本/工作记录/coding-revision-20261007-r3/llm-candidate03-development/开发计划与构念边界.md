# candidate03 开发计划与构念边界

本版本用于开发，保留 v14 正式基线。原 240 条确认材料已因参考错误台账和本次开发而暴露，不再充当 candidate03 的独立测试。A/C/T、原始单元和 v1.3/v1.4 构念均不改动。

已逐项核读 I/F 的 34 个“LLM 与至少一种 AI 参考不一致”维度。其中 12 个具备明确执行误用依据，22 个保留为参考边界分歧。后者包含 LLM 已与候选参考相符、仅与 A 或 C 不同的条目，不能统称机器错误。原台账完整记录保存在独立诊断文件中。

修订针对四类一般问题：需求迫切与实际获取缺口混淆；程序/沟通事务被扩展为实体创新支持；仅按注册序号推断创新；把“实际保障关系”误解为必须已经发生个别给付。新增正反教学例并加强当前谓词与条件承接检查，不使用真实样本 ID、部门特征、目标 κ、预计标签比例或参考答案。候选02对支持资格/研发阶段的宽泛表达改为逐案检查当前条件是否实质决定何种已明确支持；存在争议仍记录边界，不把阶段词定为一律 0 或 1。

完整手册及 v1.4 实质操作说明逐字保留；同 ID 引文隔离技术约束沿用。输出结构仍使用 LLM-binary-v32 格式家族，实际方法由 candidate03 提示词 SHA、运行请求和每批元数据识别，不能把格式版本误称与候选02相同方法。

开发调用：240 条政策单元全部重判五维（10 批），另加预先固定的 30 条合成控制（2 批）。合成控制及预期判断在调用前封存，未放入模型输入；不是政策原文或独立外部验证。控制包含 I/F 明确正类与反例，并覆盖 S/E/Ec，防止只减少阳性而提高表面一致性。全部 240 条的候选参考 I 正类为 15，F 正类为 48；稀有正类须报告具体计数，不能通过改标签或混合抽样组成“解决”。

执行模型固定 gpt-5.6-sol，reasoning effort 为 medium。批量大小 25，主开发运行并发 3，低于既有运行允许的 8。预计 12 次实际调用；只在执行、结构、逐字引文或工具事件失败时按相同请求重试，单批最多 3 次，技术上限 36 次。首次有效结果固定，全部失败尝试保留。不因语义答案不满意重抽同一请求。

开发门禁由语义依据、正反控制和实际运行完整性组成，不设 κ 达标门槛。逐项记录已确认误用是否纠正，以及所有五维变化和退步；合理参考争议不强行归零。存在系统性新误用时保留当前版本为失败或需修订开发版本；若语义检查通过，则单独封存候选并按既有授权安排 4924 条全量五维重跑，需 197 个新批次、技术上限 591 次实际调用，不复用旧维度或替换 v14。新独立验证由 root 另行统筹。
